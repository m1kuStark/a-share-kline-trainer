# 刷新与发布边界

本页说明当前实现。整批发布应满足的 `DATA-PUBLISH-ATOMIC` 见 [数据要求](../../../../docs/specs/market-data/requirements.md)；协调器路径已按整批发布实现，独立入口的能力边界单独说明。

## 当前调用链

[refresh.ts](../refresh.ts) 创建的协调器在一个实例内保留一个运行任务。第一次刷新返回 202；运行期间重复请求返回 200、相同 `taskId` 和 `joined: true`；无来源返回 409。任务状态在内存中，重启后回到 idle，历史结果仍从数据库读取。

选定来源后，协调器依次执行：读取扫描基线 → `source.scan` → 目录扫描（[catalog.ts](../../tdx/catalog.ts) `scanCatalogChanges`，只读）→ 权息扫描（[adjustment-cache.ts](../../tdx/adjustment-cache.ts) `scanAdjustmentChanges`，只读）→ 发布屏障 → 单事务整批提交。在线来源当前只走扫描及快照步骤，完整能力边界见 [来源合约](./source-contract.md)。

发布屏障是一个同步段：目录写入、权息写入、文件快照、成功日志与批次标识（`cache_meta` 的 `catalog_batch` / `adjustment_batch` / `snapshot_batch` 三键写入同一 UUID）在 `BEGIN IMMEDIATE … COMMIT` 内一次性生效；屏障检查（超时或任务已结束）与提交之间没有任何 await。任一扫描或写入失败整体回滚，上一份完整批次原样保留。

| 阶段 | 事务范围 | 失败后的实际边界 |
|---|---|---|
| 目录/权息/快照扫描 | 只读，不写库 | 任何失败整批失败，不产生半批写入 |
| 整批发布 | 协调器单事务（含三键批次标识） | 任一环节失败全部回滚，读取方只能看到上一份完整批次或新批次 |
| 失败日志 | `appendFailureLog` 独立事务 | 只追加失败日志，不动快照与缓存 |

协调器把目录扫描结果中的非空 `failures` 视为整批失败：扫描不完整时不发布任何变更（含健康市场），错误信息列出失败市场。市场级"保留旧缓存、更新健康市场"的局部回退仍保留在独立入口 `refreshStockCatalog` 中（`/api/env`、股票查询与训练查询路径使用），这些入口各自是完整的单域事务，但不写入批次标识、也不与协调器批次合并——统一入口仍是 [DATA-04](../../../../docs/work-items/tasks/DATA-04.md) 的范围。

## 超时与并发

默认看门狗为 120 秒，超时追加失败日志并结束任务状态。协调器在每个异步阶段之后和发布屏障之前检查"超时或任务已被结束"的屏障条件：迟到的扫描结果被丢弃，目录/权息阶段不可能在超时后再提交（应用与提交之间是同步段），失败任务不会被迟到步骤改写成成功，超时后新任务可安全开始、旧任务的迟到流程不得覆盖新批次。看门狗未取消底层读取本身，但读取不再有写库路径。

`/api/env`、股票查询、普通行情和训练查询等路径仍会直接触发目录或权息刷新；它们不共享此协调器的任务合并。若这些独立刷新与协调器批次并发，两者都是完整事务（node:sqlite 同步段内提交），不会互相插入半批写入，但独立刷新不携带批次标识。

## 状态、修订与历史

`data_refresh_log` 保留最近 50 次尝试，包含失败。状态响应的 `lastResult/lastCheckedAt` 取最近尝试，`sourceMaxDate/revisionWarning` 取最近成功。每次协调器整批发布都会把 `catalog_batch`、`adjustment_batch`、`snapshot_batch` 三键写成同一批次 UUID；三键存在且相等＝最后一批完整生效（缺失或不相等只可能来自旧版本数据或独立单域刷新）。本约束不重建表、不删除既有用户数据。

首扫只建基线；后续按路径、size、mtime 和最大日期识别新增、移除及疑似修订。警示不会隔离修订文件，也不会保存日线旧字节或为训练固定版本。当前训练仍读取本地文件，所以"已有训练按旧数据口径继续"的提示不构成可复现保证，读侧版本缺口见 [DATA-03](../../../../docs/work-items/tasks/DATA-03.md)。

`needsUpdate` 仅比较全市场尾日期与"今天之前最近非周末日"；法定节假日可能误报。它不判断个股停牌、区间漏数，也不参与可靠的结算覆盖证明。
