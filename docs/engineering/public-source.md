# 公开源码边界

发布使用[REL合同](release-m3-contract.md)定义的独立公开仓库。私有开发仓库与历史继续保留，不能直接切换为公开：旧提交包含真实通达信导出和个人验收资料。

`npm run release:source -- --out 新建外部目录`只从干净提交复制允许的源码、业务测试、用户文档、依赖许可及构建入口；不复制Git历史、工作区、数据库、行情或模型工具。目的目录必须在仓库外且不存在。公开package去掉私有任务、文档、候选和M1命令，业务测试及构建保留。每个文件的SHA256与私有来源提交写入SOURCE-MANIFEST.json。

发布前必须对导出目录重新执行npm ci、单测与构建，核对文档链接、许可和敏感内容，再建立独立Git历史。白名单只控制文件边界，不能代替检查文件里的数据来源。

便携版没有Git。服务端读取package.json版本以及发布工具生成的release.json；仅当appId、版本、40位提交SHA均匹配时用于录制版本元数据。损坏或不匹配的记录回退原Git检测，不能伪称已识别版本。该元数据用于定位构建，不是防篡改签名。

2026-09-21审查仍有发布阻塞：现有gbbq解码表未找到可确认的再分发授权。同表出现在MIT项目不证明其来源授权完整。解决并复核之前不得创建公开代码或资产。依赖MIT/Apache等许可文本独立保留在third-party，不把原创MIT许可套用于第三方数据。
