# GLM 失败模式与教学账本

这是控制层维护的追加式经验账本。它记录可复用的失败模式，不替代任务卡、合同、独立验证收据或用户验收。新条目必须保留首次失败、复现命令/证据和修复后的验证边界。

## 使用规则

1. 收到GLM回调时，GPT先阅读本账本，再核对当前任务卡和真实工作树。
2. 派发合同只引用与当前范围相关的条目；GLM先复现已知RED，再实现GREEN。
3. 账本条目必须区分执行者自报、GPT复核和独立验证；“测试通过”没有命令、退出码和提交绑定时只能算未验证。
4. 相同失败指纹跨attempt累计，不因新会话、新worktree或上下文压缩归零；达到合同预算后升级GPT重新规划。
5. 经验必须沉淀为测试、合同字段或范围门禁。只增加提示语而不增加可检查约束，不算完成学习闭环。

## 已验证模式

### FM-001：自报完工不等于有产物

- 现象：GLM回调给出完整文件清单、提交和测试叙述，但对应worktree HEAD、工作树和mtime搜索没有任何变化。
- 处置：以磁盘、Git和独立探针为准，报告标记 `needs_replan`；原会话归档后由控制层指定唯一写者，不采信虚构测试数字。
- 教学规则：完成回调必须携带可复核HEAD和证据路径；GPT先核对实际diff，再决定是否继续。不存在diff时不得进入产品验收。

### FM-002：字符串形状校验会放过非法日历值

- 现象：时间正则接受 `2026-99-99T99:99:99Z`、`2026-02-30T12:00:00Z`、`2026-01-01T25:00:00Z` 等不可能时间。
- 处置：补真实年月日、时分秒校验和合法闰日正例，并保留先RED后GREEN证据。
- 教学规则：凡是日期、路径、数量或协议字段，必须验证语义值，不得只验证字符串外形；把每个反例写入回归测试。

### FM-003：独立runner不能替代原协调会话

- 现象：新开的GLM runner没有继承Zcode原会话的上下文或权限，出现权限客户端缺失，返修无法写入或测试。
- 处置：产品任务优先通过Computer Use注入原Zcode协调会话；桥不可用时记录阻塞，不重复开新会话消耗额度。
- 教学规则：合同交接对象必须写明原协调会话和当前worktree；禁止把新会话的自报状态当作原会话接续。

### FM-004：长任务期间GPT轮询会消耗强模型额度

- 现象：派发后GPT持续等待、读取看板或刷新日志，GLM额度虽未耗尽，Codex额度却持续消耗。
- 处置：交接成功后立即结束GPT回合；只由Zcode在完成、失败或需要裁决时回调。
- 教学规则：等待不是验收动作。没有新事件就不读取看板、不重派、不改变合同。

### FM-005：测试全绿仍可能遗漏真实边界

- 现象：既有单测通过，但独立反例发现竞态、来源失效、事务并发、版本隔离或UI生命周期缺口。
- 处置：把反例先写成RED，再修复为GREEN，并做定向真实路径/语义验收；保留首次失败。
- 教学规则：每个共享状态、并发边界、版本路由和用户可见状态至少需要一个行为反例，不以测试数量代替覆盖证明。
