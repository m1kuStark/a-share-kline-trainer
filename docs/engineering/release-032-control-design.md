# v0.3.2 本机控制与接线设计

供[REL-03](../work-items/tasks/REL-03.md)后续小任务拆分。用户已授权首次接入和受控退出，不额外改变交易规则。先交付正常保存退出；最后标签回收须在可证明保存完整时才启用，不把浏览器关闭事件当作可靠退出指令。

## 运行身份与权限

每个便携启动记录包根、构建SHA、dataDir、数据库、固定端口、runId及配置来源。启动器生成独立随机控制令牌；令牌不写公开health、不进入录像/错误输出，状态文件不能作为普通静态资源提供。首次页面通过受保护的同源会话入口领取控制能力；必须校验Host、Origin/Fetch Metadata，并对无Origin的非浏览器原生助手用独立凭据验证，不能允许任意curl/跨站请求直接领取令牌后停止服务。

所有控制请求走固定动作和结构化参数，拒绝未知动作、跨源、失效令牌、过期runId；响应和日志不回显密钥。文件夹选择只调用固定Windows脚本和参数数组，用户路径不进入shell命令拼接。目录选择取消是正常结果。扫描可超时/取消，不默认递归整盘。

## 启动与来源配置

保持有效显式配置优先，读取顺序和实际生效项必须可解释：环境TDX_ROOT、显式--config指定的非空tdxRoot、便携包trainer.config.json明确选择、dataDir中程序保存选择、自动发现候选。自动发现只提供候选；不以第一项作为静默生效依据。

配置文件语法/编码错误不能在打开浏览器前直接退出：如果能安全确定端口与用户库，启动诊断页面；否则显示明确修复窗口/日志入口，不能猜库位置另建个人库。缺TDX可直接打开页面并导入录像，/api/env失败不能遮挡诊断或离线回放。来源检查与目录扫描不绑定到加载主页面的强制写缓存动作。

保存动作应先验证选中候选及操作状态，再以临时文件+原子替换保存；保存失败保留旧选择。活动训练不得切源。显式配置覆盖时说明设置不会生效，提供对应修复路径，不报假成功。

服务器数据协调器与AppConfig启动时固定，因此首版采用受控重启：保持原dataDir、数据库、端口和origin，旧服务正常排空退出，启动器核对旧PID/runId后加载保存配置重启。重启助手不能继续继承本次自动发现的TDX_ROOT覆盖新选择，只有用户显式环境值保留优先级。启动成功由新runId、预期数据库/来源/构建及健康响应共同确认；失败保留旧配置和回滚操作，不无限重启。

## 正常退出

退出不结算、不放弃训练。界面先冻结新的买卖/画线操作，等待在途请求、绘图持久化及录像写入完成；持久化失败给重试/取消。多个页面分别登记并协调保存；任何其他页面拒绝或未确认时不强制结束它的服务。

服务端进入draining后拒绝新业务写入，等待已接受请求结束，关闭Fastify和SQLite，再退出进程。客户端“请求已接受”不等于端口已释放：停止助手需验证归属PID退出和端口结果，保留Start/Stop互斥与身份拒绝。浏览器不能可靠关闭脚本未创建的标签页，完成页面显示“已退出，可关闭此页”，不假称已关闭浏览器。

Stop.cmd保留应急能力；原SIGKILL路径不能作为新按钮的正常退出。需要升级到正常退出时优先调用受保护协议，只有用户明确执行应急动作才允许身份核验后的强制结束，并显示可能未保存风险。

## 最后标签延迟回收

独立页面会话标识，关页提示仅辅助；刷新、回退缓存恢复和短暂重连有宽限。其他有效页面或未确认保存存在时不退出；visibilitychange、最小化或短期心跳丢失不等于关页。浏览器冻结与崩溃/睡眠不可完美区分，v0.3.2若无法通过边界回归则交付明确的保存退出入口并把自动回收列为已评估未启用，不假报“关页立即释放端口”。--no-open、开发测试和自管服务不受自动回收控制。

## 后续分工与验证

1. GLM小任务只读Windows线索采集：进程路径、桌面/开始菜单链接、安装记录、常见目录；输出候选路径及来源，不写其他模块。与TDX-CHECK-01组合。
2. GLM小任务原生目录选择与原子配置模块：固定本机桥、取消/错误/覆盖优先级，独立测试；不接服务器。
3. GLM小任务退出会话状态机：纯逻辑和保存协调规则；集成人随后接API/App/启动器，避免同文件并写。
4. 创建范围的服务端迁移/API与录制枚举兼容分开小任务；界面在合同稳定后实施。新模式不伪装成已有3M；旧训练和v1/v2录像必须可读。
5. 发布新增脚本须同步源码导出、build required/allowlist/staging与清单测试。干净包在没有手写JSON、中文/空格路径、多安装、缺数据、取消、保存失败、刷新、多标签、休眠、重复启停、升级保留原库/浏览器录像下验收。完整候选门禁后才发布v0.3.2。
