# 文档与状态更新协议

## 事实归属

产品行为在specs；模块实现说明在代码旁；任务和阶段状态在work-items；测试/视觉/用户验收事实在verification；status从卡片生成。历史放archive、未实施设计放proposals，重要决定一项一页放decisions。

日期只是编辑时间，不等于验收。实现、分支自测、集成、主代理视觉、用户阶段验收分别记录；证据不足填未记录。

## 更新触发

| 变化 | 任务实现者 | 集成人 |
|---|---|---|
| 行为/边界 | 规格、回归、任务卡 | 范围和阶段审查 |
| API/模块/数据格式 | 合约、模块正文 | 跨模块依赖 |
| 新增/移动/删除文件 | 最近索引、反向链接 | 全仓链接检查 |
| 纯实现调整 | 文档影响及理由，失真正文仍要改 | 审查理由 |
| 测试/人工检查 | 新验证记录，保留失败和重试 | 关联候选提交 |
| 合并/回滚/验收 | 任务交接 | 集成引用、阶段卡、status |
| 中断 | 阻塞、未提交改动和下一步 | 接续时核对基线 |

更新在确定范围、完成可验证行为、交接、提交及集成这些检查点发生，不必每条命令都写日志。代码、测试与受影响正文一起交付；无文档影响写具体理由，禁止只改日期充数。

## 可执行命令

```powershell
npm run docs:check
npm run docs:impact -- --base <基础SHA> --task <任务ID>
npm run docs:status
npm run docs:status -- --check
```

check校验当前链接/锚点、任务元信息/ID/引用及规范命名；历史旧引用只警示，当前入口不得断链。impact包含未跟踪源码，检查路径范围和文档影响。status只改标记生成区；worker更新自己任务，集成人生成全局页，不各自改全局进度。

这些检查已接入 `verify:baseline`；它不是远端分支保护，当前未启用自动CI拦截。审核仍需判断文字与证据是否真实，脚本不能证明用户同意或测试充分。工具实现与边界见[脚本](../../scripts/README.md)。

## 验证与提交的先后

优先对提交C运行验证，后续证据提交E引用tested_commit=C。只含报告/任务元信息的E单独过文档检查，明确继承C运行结果；改变源码、配置、测试或门禁必须重新验证，不能把所有md都当无影响。

提交前在工作树验证时保存精确源码/配置/测试指纹，提交后核对同一文件集合；报告标明工作树自测和映射提交的方式。禁止amend产生新SHA后继续声称旧证据测过新提交。用户验收另存准确范围、来源、时间，不由自动化推断。

## 清理

新bug的根因和回归写入任务及验证记录，停止向历史changelog、旧testing添加过程。关闭任务路径稳定，从活动摘要移出；旧规范标后继入口。保留必要兼容页，避免制造两份正文。临时.run产物与Headroom全局缓存不入Git，正式证据和用户数据不自动删除。
