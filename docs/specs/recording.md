# 操作录制、复盘与分享

状态：已集成，用户2026-09-21阶段验收（[验收记录](../verification/2026-09/M3-user-acceptance/record.json)）；工程证据以[REC-01任务](../work-items/tasks/REC-01.md)为准。

## RECORDING-DEFAULT

录制默认开启。首页和训练中都有开关，顶部持续显示状态；用户可暂停/恢复。失败不得假显示成功。每场新训练默认开启，同页刷新保留本场暂停状态。结束默认保留历史，明确取消仅丢弃本场录像，历史不自动删除。

## RECORDING-PURPOSE

记录用于自动测试、bug复现、复盘和分享。业务列表只呈现买卖/拒单及图形文字变更；推进用于交易日轴，保存同期已见日线让回放自由切日/周/月。主题、工具选择、加载和保存不算业务操作。记录版本、数据、实际结果和顺序。

暂停/恢复本身保留元事件；暂停期间标记未记录区间，恢复时保存新的完整状态检查点，不能伪造遗漏操作或宣称连续完整。

分享由用户主动导出，不自动上传。接收者使用K线训练器即可导入查看；分享包携带所需行情/权息、规则、初始状态及操作，不依赖发送方本地路径。未完成训练的分享只带已可见区间，回放逐步截断；版本/数据不兼容时明确提示或只读展示，不能静默产生不同结果。

## 验收边界

复盘展示还原当时记录；业务重放重新执行并比对数值；真实UI重放用实际鼠标键盘验证完整交互。三者分别报告，不能以写内部状态代替真人流程。精确重放依赖数据/规则冻结；现有缺口见[DATA-03](../work-items/tasks/DATA-03.md)、[TRAIN-01](../work-items/tasks/TRAIN-01.md)。

使用schemaVersion=2紧凑记录：语义事件、不可变行情/图形版本、实际账户结果和轻量检查点；只导出`.trainer-session.json.gz`。旧v1 JSON/浏览器记录按需迁移，原存储保留。回放只读并按交易日取当时版本，不重复成交。

**范围录像（schemaVersion=3，TRAIN-02 第二片冻结合同）**：任一录像包含RANGE训练元数据必须以v3持久化（`range.version=1`沿后端TrainingRangeMeta；tier哨兵RANGE不伪装五档），v2+RANGE为禁止的中间态；新读取器兼容v1/v2/v3，v1/v2只接受旧五档（旧档伪装五档携带range在任何版本拒绝），v3容纳创建前null检查点；未知版本显式拒绝。版本升级与首次RANGE持久化一致。旧训练继续v2，既有文件不破坏性重写。

导入压缩体积25MiB、v2解压JSON128MiB、旧v1迁移256MiB；事件50000、轻量检查点20000，资源预算与取消规则见v2合同。无效文件拒绝且不改变现有训练；这些是导入保护，不是自动停录。两年正常训练必须支持完整记录/导出。规则自TRAIN-01起来自本局创建时冻结的快照（origin/capturedAt 以可选元数据透出，见[训练规则](training/rules.md) TRAIN-RULE-SNAPSHOT），旧录像缺字段按原reader读取；全局默认修改后已冻结规则与录像不漂移。

录制准备阶段阻止操作，失败明确提示后允许继续训练并提供重试。复制标签页若已有录制写者，本页建立独立录制；原场不被覆盖。暂停恢复与未记录区间持续显示，失败期间不声称遗漏操作已被记录。

现行格式见[v2接口](../engineering/recording-v2-contract.md)，旧格式见[v1兼容合同](../engineering/recording-contract.md)，设计理由见[紧凑方案](../proposals/session-recorder/compact-storage.md)。后续确定性业务重算仍受DATA-03约束（规则冻结已由TRAIN-01交付）。


## 本轮用户返修口径

用户明确要求业务列表/计数只呈现买卖与图形文字变更；推进用于交易日时间轴，暂停缺口仍保留为元数据，界面主题/工具选择/图表加载不作为业务事件。录制区位于顶部，不占账户仪表盘；只提供gzip导出，旧JSON继续可导入。首页/侧栏明确提供训练录像库，活动训练往返不会结束。

结束/放弃默认保留本机历史，取消仅删除本轮录像，不动成绩与画线；保存失败不假装完成。结束后的刷新只读取已有录像，不自动创建新录像。按日回放及独立周期观察已随v0.3.2发布交付，工程验收见[REL-03回放记录](../verification/2026-09/REL-03/recording-daily-journey.json)；返修口径见[返修合同](../engineering/stage-feedback-20260919.md)。

## 录像库与安装实例隔离

安装实例的 `recordingNamespace` 由服务端生成并保存在当前训练数据库中，稳定且不含本机路径。前端完成 `/api/env` 初始化后，才可以访问本机录像库；本机 v2 录像和导入录像使用由该命名空间派生的独立浏览器存储。默认便携包各自使用安装目录的 `data`，不同独立数据库之间不会互相覆盖；显式共用同一训练数据库时沿用该数据库的录像库标识。命名空间缺失或为空时拒绝访问，不能回落到未隔离的公共库。

训练录像库页面分为“本机训练录像”和“导入的分享录像”两栏。导入录像先按现有格式校验及迁移，再以新的 `imported-*` 存储 ID 保存；文件中的原 `sessionId` 只作为 `originalSessionId` 元数据保留，回放通过导入条目的新 ID 定位。当前命名空间中的本机录像继续按原 `sessionId` 读取，旧 v1 录像仍按需迁移并保留原条目。未隔离的旧公共库不删除、不自动归入某个安装实例，旧 v1 文件仍可导入。

用户可以删除单条录像，也可以按来源清理整栏。删除本机录像前必须通过活动训练和跨标签页写者保护；当前训练或仍在录制的录像不删除，并返回可行动的失败原因。导入录像可以独立删除或清理，不会删除本机训练录像。清理结果逐条报告成功与失败，不能把受保护条目伪报为已删除。
