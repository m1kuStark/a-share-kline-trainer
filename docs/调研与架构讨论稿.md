# A 股 K 线训练器 · 调研与架构讨论稿

> 日期：2026-09-03　状态：**讨论稿（待拍板）**
> 结论先行：开源社区**没有**同时满足「通达信本地数据 ＋ 逐日收盘价训练 ＋ 丰富划线工具 ＋ 分档排行榜」的现成项目；但三个关键部件都有成熟可复用件——图表与划线用 **klinecharts v10**，通达信数据格式有权威参照（pytdx 等），训练交互规则可对标 **KlineTrain**。路线：**复用组件 + 自建训练器**，不 fork。
>
> 本机数据链路已于 2026-09-03 实测打通（见 §二），解析出的 OHLC 与真实历史逐日吻合。

## 一、开源调研结论

### 1.1 有没有现成工具？——没有四项全中的

| 项目 | 形态 / 热度 | 协议 | 与本需求的关系 |
|---|---|---|---|
| [pangzhongyu666/KlineTrain](https://github.com/pangzhongyu666/KlineTrain) | Android(Kotlin)，13★，2026-08 仍更新 | MIT | **最接近的"训练器"**：真实历史盲走模拟交易、双盲（藏股票名/日期）、分仓、止盈止损、结算含手续费、权益曲线、段位制（青铜→王者）、战法统计（胜率/盈亏比）。→ **交互与规则设计的主要对标**。差距：在线数据（腾讯接口）、无划线工具、无分档排行榜 |
| [klinecharts/KLineChart](https://github.com/klinecharts/KLineChart) v10.0.3 | Web 图表库，4109★，2026-08 活跃 | Apache-2.0 | 图表 + 划线**直接复用**（详见 §3.4/§4） |
| [rainx/pytdx](https://github.com/rainx/pytdx) | Python 数据库，1554★，已归档 | 无 license | .day / gbbq 格式**权威参照**（参考重写，不复制代码） |

### 1.2 同类产品沉淀的经验准则

1. **训练循环的标准形态 = 盲走**：先给一段历史 K 线，逐日推进，推进前看不到未来；买卖按最新已放出 K 线的收盘价成交。通达信自带训练模式（功能 → 专家系统 → 训练模式，空格键放下一根、`.326` 隐藏其后数据）即此形态——本工具与其对齐。
2. **排名惯例**：单一收益率最常见但鼓励满仓梭哈；券商/赛事常用**三级字典序：收益率 → 最大回撤 → 胜率**，并配**最小交易笔数门槛**防"空仓躺赢"；正式赛事有回撤淘汰线，训练器可简化为"破产线"（KlineTrain：权益跌到初始 5% 判破产重开）。
3. **结算指标标配**：总收益率、最大回撤、胜率、盈亏比、交易次数、权益曲线；进阶加相对基准超额。
4. 防作弊在线产品靠服务器；本地单机靠**数据接口级截断**（API 只发到当前推进日）＋ 自律。
5. 成交口径**统一比精细更重要**（已拍板：当日收盘价成交）。

## 二、本机数据可行性实测（2026-09-03 全部验证通过）

| 项 | 实测结果 |
|---|---|
| 通达信安装目录 | `D:\MySoftWares\TDX`（实测时 TdxW.exe 正在运行，只读访问无冲突） |
| 日线数据 | `vipdoc\sh\lday` 6017 个 .day；`vipdoc\sz\lday` 5860 个；**北交所在 `vipdoc\bj\lday`**，348 个（bj 代码段） |
| 数据新鲜度 | 全部更新至 **2026-09-02**（每日盘后由通达信自动更新，训练器只读） |
| .day 格式 | 无文件头，**32 字节/条、小端序**：日期 int32(YYYYMMDD) ＋ 开高低收 int32(0.01 元定点) ＋ 成交额 float32(元) ＋ 成交量 int32 ＋ 4 字节保留。实测校验：sh000001 首条=1990-12-19 开 96.05/收 99.98 ✓；sh600519 首条=2001-08-27 开 34.51/收 35.55、末条=2026-09-02 收 1297.50 ✓；文件长度均为 32 的整数倍 |
| 价格系数 | A 股价格 ×0.01、量 ×1；指数价格 ×0.01；B 股不同（不做）。只做沪深 A 股（＋北交所可选），系数表固定即可 |
| 代码-名称对照 | `T0002\hq_cache\shs.tnf / szs.tnf / bjs.tnf`（GBK 名称、记录内偏移不固定，需扫描解析）；`base.dbf`（dBASE III，含 GPDM 代码字段，8190 记录）可作兜底 |
| 权息（复权） | `T0002\hq_cache\gbbq` 存在且每日更新。格式已考证：29 字节/条（3×8 字节 Feistel 加密块＋5 字节明文），category=1 为除权除息 → **做前复权的技术条件已具备**，v1 可不做 |
| 基准指数 | sh000300（沪深300）、sh000905、sh000852 日线齐备，可算超额收益 |
| 运行环境 | Node v24.15.0 可用（已用 Node 实测解析 .day 通过）；Python 仅 3.9 |

结论：**数据层零外部依赖**——不联网、不爬接口，本地数据每日自动更新，历史深度足够 2 年档训练。

## 三、产品功能设计（讨论稿）

### 3.1 训练主流程

1. **选股票**：搜索（代码/名称包含匹配）＋ 市场筛选（沪/深/北，可只看主板）
2. **选周期档**：1 个月 / 3 个月 / 6 个月 / 1 年 / 2 年（决定排行榜归属）
3. **选起始日**：日期选择器（限数据范围内）；可选"随机盲选"
4. **载入训练**：起始日之前约 250 根 K 线作为可见历史（供指标/形态分析），起始日即训练"今天"
5. **逐日推进**：空格键或按钮放下一根 K 线（对齐通达信训练模式习惯）；推进前可画线、可下单
6. **下单**：买入/卖出（按仓位比例），按**当日收盘价**成交，二次确认防误触；成交后自动维护**持仓成本价位线**（一根水平线随成交实时更新）
7. **结算**：手动"提前结算"（按当日收盘清仓）或到期自动结算；成绩写入该周期档排行榜
8. **复盘**：结算后回看全程 K 线 ＋ 全部 B/S 成交点 ＋ 画线 ＋ 权益曲线

### 3.2 成交与账户口径（默认建议）

- 成交价 = 操作当日收盘价（已拍板）
- 股数 = 金额 ÷ 收盘价，**向下取整到 100 股**（整手）；卖出支持部分卖出（按股数或比例）
- **T+1**：当日买入次日才可卖（默认开，可关）
- 手续费：**默认 0**（对齐通达信训练模式）；可开启（佣金万 2.5、最低 5 元 ＋ 卖出印花税 0.05%）
- 涨跌停/停牌：不模拟（停牌日自然无 K 线；涨停日收盘仍可成交，与通达信训练一致）
- 初始资金：默认 100 万，创建训练时可改
- 成本价 = 摊薄成本（含费）；减仓不改变剩余持仓成本；成本线随加/减仓自动刷新
- 排行榜 = 本机历史训练成绩（单人）；日后要多账户再加 user 表即可

### 3.3 周期分档与排行榜

- 档位：**1M / 3M / 6M / 1Y / 2Y**（按自然月定义），各档独立排行榜、互不干扰；到期日 = 起始日后满足档位时长的第一个交易日（.day 数据本身即交易日历）
- 排序（建议）：**总收益率 → 最大回撤 → 胜率** 三级字典序；列展示盈亏比、交易次数、相对沪深300超额、提前结算标记
- 防躺赢：可选最小交易笔数门槛（如 ≥3 笔才计排名）——待拍板
- 破产线：权益 ≤ 初始 20% 提前判负结算（可选）——待拍板

### 3.4 划线工具 × klinecharts v10 映射

| 需求 | 实现方式 |
|---|---|
| 线段 / 射线 / 直线 | 内置 `segment` / `rayLine` / `straightLine` |
| 价位线 | 内置 `horizontalStraightLine` |
| 圆弧 / 圆圈 / 矩形 / 文本 | **自定义 overlay**（v10 未内置，`registerOverlay` 实现，各约几十行） |
| 百分比线 | **自定义 overlay**（两点间按 % 画水平线组） |
| 红/绿箭头（看涨/看跌标记） | **自定义 overlay**（实心三角箭头） |
| 买入点 / 卖出点标记 | 自定义 overlay（B/S 图标＋价格股数提示），由训练引擎实时创建 |
| 成本线 | 程序化 `createOverlay`（水平价位线），锁定不参与鼠标交互 |
| 画线持久化 | `getOverlays()` 序列化 JSON 存库，重开时 `createOverlay()` 重建（官方实践） |

klinecharts v10（Apache-2.0）内置 16 种 overlay，点吸附/磁吸/生命周期回调齐全；**指标内置 MACD、MA、VOL**——与骑牛登山体系（MACD 为核心）天然匹配。自定义 overlay 共 6 个，工作量数天级。

### 3.5 版本规划（建议）

- **M1 数据层**：通达信目录自动发现 ＋ .day/名单解析 ＋ 股票搜索 API（可独立验收）
- **M2 训练核心**：K 线图 ＋ 盲走推进 ＋ 买卖/仓位 ＋ 成本线 ＋ 结算（暂无划线）
- **M3 划线工具**：内置 overlay 接入 ＋ 6 个自定义 overlay ＋ 持久化
- **M4 排行榜**：分档结算入库 ＋ 排行页 ＋ 复盘回看
- **M5 打磨**：随机盲选/双盲开关、费用与 T+1 开关、快捷键、权益曲线、破产线

## 四、技术架构（推荐方案）

### 4.1 选型：本地 Node 服务 ＋ 浏览器（方案 A）

```
┌────────────────  浏览器 (localhost)  ─────────────────┐
│  Vue 3 + Vite + TypeScript + klinecharts v10          │
│  训练界面 / 划线工具栏 / 下单面板 / 排行榜 / 复盘      │
└───────────────▲───────────────────────────────────────┘
                │ REST (JSON)
┌───────────────┴───────────────────────────────────────┐
│  Node.js (Fastify/Express) 本地服务                    │
│  ├─ 数据管道：TDX 路径发现 → .day/tnf/dbf 解析 → 缓存  │
│  ├─ 训练引擎：状态机(盲走/撮合/仓位/结算)＋数据截断   │
│  └─ SQLite (better-sqlite3)：训练/成交/排行/画线      │
└───────────────▲───────────────────────────────────────┘
                │ 只读
      D:\MySoftWares\TDX\vipdoc\{sh,sz,bj}\lday\*.day
      D:\MySoftWares\TDX\T0002\hq_cache\{shs,szs,bjs}.tnf、gbbq
```

- **为什么不是 Electron**：打包重、维护成本高；`npm start` 起服务开浏览器同样单机可用，且同类 Web 组件生态最全
- **为什么不是纯前端**（File System Access API）：目录授权跨会话不稳定、做不了路径自动发现，排行持久化还得另配 IndexedDB
- **为什么不是 Python 后端**：可行（pytdx 生态），但前后端两种语言两套工具链；.day 解析 Node 十行搞定，全 TS 单语言最省
- 通达信运行中只读 .day 无冲突；数据更新仍由通达信盘后下载负责

### 4.2 防未来数据（训练可信度的根）

- 图表数据一律经训练引擎发放：`GET /api/trainings/:id/bars` 只返回 ≤ 当前推进日的 K 线
- 原始 `/api/kline` 仅在**已结算**（复盘）状态开放
- 截断在服务端完成——前端**拿不到**未来数据，而不是"看不见"

### 4.3 数据层要点

- 路径发现三重兜底：① 注册表 `HKCU\Software\TDX`（线索级）② 常见路径枚举 ③ **目录特征校验**（`vipdoc` ＋ `T0002\hq_cache\gbbq` 同时存在）；最终允许手动指定并持久化
- 名称解析：tnf 为主、base.dbf 兜底，GBK→UTF-8（实现时以本机文件实测校准记录步长）
- 缓存：SQLite 建 stocks 表（代码/名称/市场/bar 数），按 .day 文件 mtime 增量刷新
- v1 不复权（对齐通达信默认看盘与体系口径）；gbbq 前复权作后续开关

### 4.4 存储草案（SQLite）

```sql
settings(key TEXT PRIMARY KEY, value TEXT)          -- tdx路径/初始资金/费率/开关
trainings(id PK, tier, code, name, start_date, planned_end, settle_date,
          status, initial_cash, final_equity, return_pct, max_drawdown_pct,
          win_rate, pl_ratio, trade_count, benchmark_return_pct,
          early_settle, created_at, settled_at, note)
trades(id PK, training_id FK, seq, trade_date, side, price, shares,
       amount, fee, cash_after, shares_after, cost_after)
drawings(training_id PK, payload TEXT)              -- overlay JSON
```

### 4.5 API 草案

```
GET  /api/env                        服务状态/TDX路径/数据截止日
GET  /api/stocks?market=&q=          搜索股票
POST /api/trainings                  {tier, code, start_date, initial_cash}
GET  /api/trainings/active           当前训练（可见K线＋账户状态）
POST /api/trainings/:id/next         推进一日 → 追加一根K线＋状态
POST /api/trainings/:id/trade        {side, weight|shares} 按当日收盘成交
POST /api/trainings/:id/settle       结算（early=true 为提前结算）
PUT  /api/trainings/:id/drawings     保存画线
GET  /api/rankings?tier=6M           分档排行榜
GET  /api/trainings/:id/replay       结算后复盘（全量K线＋成交＋画线）
```
