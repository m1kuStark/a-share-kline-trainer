> **口径修订十一（2026-09-06，用户 M2 二次验收预检第六轮）**：
> ①**缩放下限放开**——可见根数下限由 10 改为 **1**：不管框选选中几根 K 线都按选中范围放大（柱宽上限内尽量铺满），不再出现"选中过少退化为平移"。根因双层：自建 MIN_COUNT=10 钳制 + **klinecharts `barSpaceLimit.max=50px`（单根柱宽上限），请求柱宽超限被静默忽略**（选中少于约 18 根时柱宽>50px → setBarSpace 无效只剩 scrollToDataIndex＝纯平移）。修复：MIN_COUNT=1、初始化时把库内 barSpaceLimit.max 提到 300（`_chartStore.getLayoutOptions()` 返回活对象，依赖钉定的 10.0.3，升级需复查）、所有 setBarSpace 过 `clampBarSpace(≤300)`。提示条改"缩放 1~420"。
> ②**420 语义修正：同屏最大可见根数（缩放下限），不是加载总量**——初始仍载 620 根（420 可见＋200 均线暖机），但用户把视窗移到已加载窗口之前时**动态加载更早历史**：服务端 `trainingBarsBefore(before, count)`（同一"截断→前复权(基准=推进日)→聚合"管线后取严格早于 before 的最近 count 根，默认 300、上限 1000、带 hasMore）；路由 `GET /api/trainings/:id/bars?before=&count=`（before 校验 YYYY-MM[-DD]，count 校验 1~1000）；前端 klinecharts 原生无限滚动——dataLoader `type==='forward'`（可视范围触达左缘 from===0 时触发）→ 按已加载最早日期取下一批 → `callback(older, {forward: hasMore})` 库自动前插。KlineChart 组件内持有累进数据（loadedData），Training 提供 `fetchEarlier`。
> **两条关键教训（本轮调试中定位）**：
> （a）**库的 forward 前插是自锚定的**（可见范围＝diff+total 推算，diff 不变、total 增 N → 同名日期不动）——**不要自己再加"锚定/补偿滚动"**：额外 scrollToDataIndex 每次多滚约一屏，把滚动差值打到负极限，视图塌缩到 4 根并引发加载风暴（total 膨胀到 3720/4960）。
> （b）**动态加载的 before 取自 loadedData[0].date，而 KLineData 只有 timestamp**——toK 映射若不保留 date 字段，before 恒为 undefined → 请求退化为"无 before 的最新 620 根窗口"且被反复前插（total 4960=620×8，时间轴错乱）。toK 现显式携带 date，加载前校验 `first?.date`。
> 验证：数据全程严格单调、total=unique 零重复；连续滚动加载到该股数据起点附近（2008 年）无塌缩无风暴；窄框选 155→5 根铺满主图。

> **口径修订十（2026-09-06，用户 M2 二次验收预检第五轮）**：**程序化缩放前恢复纵轴自动适配**——价格轴拖动/滚轮缩放是用户确认的理想功能，但它把 klinecharts 纵轴置为**手动模式**（库内 `setRange`→`_autoCalcTickFlag=false`，范围冻结；库内解除方式＝双击价格轴）。此后框选/键盘/复位缩放改变可见 K 线时纵轴不再自动适配，图表整体在轴上漂移、多次后移出视图。修复：新增 `restoreYAxisAutoFit()`（`chart.getYAxes({})` 取全部纵轴实例 `setAutoCalcTickFlag(true)`，`buildTicks` 在 flag=true 时按可见数据重建范围），在**框选右滑/左滑、键盘缩放 zoomBy、Home 复位**四条程序化缩放路径执行 setBarSpace 之前调用；价格轴的手动缩放体验不受影响（只在下一次程序化缩放时恢复自动）。

> **口径修订七（2026-09-06，用户 M2 二次验收预检，页面区域定义拍板并固化）**：
> **页面四区域定义**（自左至右、自上而下）：
> ①**菜单栏**（左侧树状栏）：切换训练视图、排行视图、复盘视图、设置视图等，是浏览与使用训练器多种功能的入口导航；
> ②**信息栏**（主页面上方）：展示当前训练上下文与股票数据（股票名称/代码、起始时间、当前时间、复权方式等），并提供周期切换（日 K/周 K/月 K）、快捷键提示等辅助信息；含全局顶栏（产品名/主题切换/数据连接状态）、训练头部、工具条与状态提示条；
> ③**训练主界面**（下方主区域）：主图＋副图＋训练实操区，用户在此用鼠标完成一切看盘与操作（框选、缩放、十字光标、平移，以及未来的绘图功能），是训练用主界面；
> ④**训练控制台**（右侧栏）：账户金额、盈亏百分比、可用资金、持仓市值、摊薄成本、当前持仓、下单控制按钮、成交记录，是模拟训练账户的信息展示与操作仪表盘。
> **硬性规则：用户对主图内容的一切操作（Box Select、缩放、绘图等）及其产生的视觉元素（如框选矩形）必须限制在训练主界面内，不得侵入菜单栏、信息栏、训练控制台等任何其他页面区域。**
> **最新价线配色修订**（替代口径修订五③"跟随最新 K 线阴阳"）：最新价线（线体＋轴侧价位标签）按**涨跌相对前收**国内配色——涨红、跌绿、平灰。真因查明：klinecharts v10 线体颜色由库内 `CandleLastPriceView` 按 `priceMark.last.upColor/downColor/noChangeColor`（compareRule 默认相对前收）自动计算，`line.color` 是不参与绘制的死键，而这三个方向色键的**默认值是国际惯例绿涨红跌**，此前从未覆盖——这正是"股价上涨线为绿、下跌为红"的来源；轴侧标签底色走 `text.backgroundColor`（可覆盖）才显得半对半错。修复：主题里显式覆盖三个方向色键（两主题通用、主题切换不会冲掉），标签底色由 `applyLastPriceStyle()` 按同一口径（相对前收）重涂。教训沉淀：**复用开源工程时必须多做一步适配审查（配色惯例、单位、日期格式等），不能直接照搬；覆盖第三方库样式前要读它的绘制源码确认真正生效的样式键。**
> **口径修订六（2026-09-06，用户 M2 二次验收反馈，M2 基线定义修正）**：①**文本标注与画线持久化彻底移除**——此前回退时把"文本面板＋drawings 后端"误判为 M2 遗产保留，用户拍板：文本/画线功能属于 M3，M2 基线不含它们；现全栈删除（前端面板/overlay/防抖保存、服务端 PUT/GET drawings、drawings 表、saveDrawings/getDrawings），B/S 标记与成本线（真正的 M2 功能）保留；②**框选图层化**——框选缩放只属于主图背景层，仅 candle_pane 区域左键按下才启动；副图/坐标轴不触发；B/S 与成本线均为 ignoreEvent 纯渲染层；③**框选双向语义**——右滑＝选中区间放大铺满主图，左滑＝按滑动距离比例缩小（新可见根数＝当前根数×可绘宽/左滑距离，右端锚定）；④**方向键语义**——↑ 放大、↓ 缩小（对齐直觉，M2 原实现相反）；⑤**一屏排版**——训练页高度=100vh−全局顶栏（CSS 变量 --topbar-h），默认状态主图+双副图+交易面板全部可见，无需滚动。

| 14 | 指标 | V1 仅 **MA25/60/144**（随周期切换）＋**VOL 副图**；MACD 及其他指标 → V2 |

| 16 | 复权 | **默认前复权**（对齐通达信看盘）；设置页可改默认为不复权；**复权方式在创建训练时锁定**，训练中不可切换 |

## 二、产品规格

### 2.1 训练主流程

选股票（搜索＋市场筛选，含随机盲选）→ 选周期档 → 选起始日（或随机）→ 载入起始日前 **420 根** K 线为可见历史（缩放 10~420）→ 空格/按钮逐日推进 → 随时买卖（可长期空仓）→ 提前结算或到期自动结算 → 成绩入档 → 复盘回看。

### 2.2 图表交互（键盘优先，对齐通达信习惯）

- **↑/↓ 方向键**：以最新 K 线为锚点缩放，可见根数 10~420（默认初始约 150 根）。实现上以当前视图右端为锚——默认状态即最新 K 线；框选历史后围绕该区域右端伸缩
- **鼠标左键框选**：在历史 K 线上按住左键拖出矩形，松开后所选区域内 K 线自动缩放至适应窗口。典型用法：先 ↑ 拉满 420 根纵览，再框选目标区域细看
- **←/→ 方向键**：呼出并移动十字光标（逐根移动，信息条同步显示该根 OHLC/成交量/日期或相对日）；光标触及窗口边缘时视图自动跟随滚动
- **滚轮**：横向平移浏览历史；**Home 键/双击空白处**：回到最新 K 线并恢复默认视图
- 推进＝空格；输入框聚焦时快捷键自动失效；训练推进后若视图停在右端则自动跟随新 K 线

### 2.3 周期与均线

- 周期切换：日K/周K/月K。服务端由日线聚合（先复权后聚合，对齐通达信：周=周一~周五、月=自然月；未走完的周/月为形成中的实时 K 线；仅聚合 ≤ 当前推进日数据，防未来）
- 均线：每个周期各自计算并显示 **MA25、MA60、MA144**（对齐体系口径），三色区分
- 训练推进粒度恒为"日"；周/月仅为观察周期切换

### 2.4 训练规则

- 买入：仓位比例档（10/20/25/30/50/75/100%＋自定义），金额÷收盘价**向下取整到 100 股**，不足一手拒绝并提示
- 卖出：按持仓比例或股数部分卖出，可清仓
- T+1：当日买入次日可卖（默认开，设置可关）
- 成本价＝摊薄成本（含费），减仓不改剩余持仓成本；**成本线**＝持仓期常驻水平价位线，随成交实时刷新，锁定不参与鼠标交互
- **B/S 点**：每笔成交打标记（含价格、股数）
- 涨跌停不模拟；停牌日自然无 K 线（结算日取到期日前个股最后交易日）
- 单训练进行中；可"放弃训练"（不入榜，记录留档）

### 2.5 结算与排行榜

- 指标：总收益率、最大回撤、胜率（盈利笔/平仓笔）、盈亏比、交易次数、相对沪深300（sh000300）同期超额、权益曲线
- 排行榜页 5 个档位标签：**"完整周期成绩"主列表**按收益率→回撤→胜率字典序；**"提前结算成绩"独立分组**（按收益率排序，标注实际天数），不与正常成绩混排
- 结算后生成成绩单（指标＋成交明细＋权益曲线）

### 2.6 双盲模式

- 开启时：顶部信息栏显示"盲训"（无代码/名称），日期轴显示相对序号（日/周/月三种周期下均相对化）
- 创建训练时的开关；设置页"双盲默认开启"
- 结算后复盘页显示真实代码/名称/日期

### 2.7 复权口径

- 默认**前复权**：基于 gbbq 权息文件解密计算复权因子，对 OHLC 仿射变换；以最新数据日为基准（新除权事件后历史价整体平移，与通达信行为一致）
- 复权方式创建训练时锁定；默认值在设置页可改（前复权/不复权）
- 分红送转不单独模拟入账，收益通过前复权价格自然体现（总回报口径）

### 2.8 划线工具（14 类全量）

| 需求 | 实现方式 |
|---|---|
| 线段 / 射线 / 直线 | klinecharts 内置 segment / rayLine / straightLine |
| 价位线 | 内置 horizontalStraightLine |
| 圆弧 / 圆圈 / 矩形 / 文本 | **自定义 overlay**（registerOverlay） |
| 百分比线 | **自定义 overlay**（两点间按 % 画水平线组） |
| 红/绿箭头（看涨/看跌标记） | **自定义 overlay**（实心三角箭头） |
| 买入点 / 卖出点标记 | 自定义 overlay（B/S 图标＋价格股数提示），由训练引擎实时创建 |
| 成本线 | 程序化 createOverlay（水平价位线），锁定不参与交互 |
| 画线持久化 | getOverlays() 序列化 JSON 入库（区分用户画线与引擎标记），重开训练恢复 |

其余内置图形（价格通道线、平行直线、斐波那契线、画笔等）一并接入工具栏。

### 3.1 技术栈

- 后端：Node.js 24 ＋ TypeScript ＋ Fastify；SQLite 用 Node 24 内置 **node:sqlite**（零原生编译依赖；不满足再退 better-sqlite3）

- 数据：只读 `D:\MySoftWares\TDX`（自动发现，允许手动指定）；训练器永不写通达信目录

### 3.3 数据层

- 路径发现四重：注册表 `HKCU\Software\TDX` → 常见路径枚举 → **特征校验**（`vipdoc\{sh,sz,bj}\lday` 有 .day 且 `T0002\hq_cache` 存在）→ 设置页手动指定；结果持久化
- .day 解析：无文件头、32 字节小端（日期 int32 YYYYMMDD＋OHLC int32 分＋成交额 float32＋量 int32＋4 保留），价格 ×0.01；按日期区间二分定位；校验文件长为 32 整数倍
- **gbbq 解密与前复权**：文件头 4 字节记录数；每条 29 字节＝3×8 字节 Feistel 加密块＋5 字节明文；密钥表 4176 字节（pytdx 公开常量移植为 TS）；明文＝市场＋代码＋日期＋类别＋4×float（分红/配股价/送转/配股）；前复权因子 m=(10＋送转＋配股)/10、c=(分红−配股价×配股)/10，按事件日期向前链式累计；因子缓存入 SQLite
- 名称：shs/szs/bjs.tnf（GBK）实测校准步长，base.dbf 兜底
- 周K/月K：服务端聚合（先复权后聚合）

### 3.4 防未来数据（训练可信度的根）

K 线一律由训练引擎发放：`GET /api/trainings/:id/bars?tf=1D|1W|1M` 服务端截断至当前推进日（周/月也只聚合到当前日），右端多备约 200 根供 MA 暖机，前端窗口显示 10~420 根；原始行情接口仅在**已结算**（复盘）状态开放——前端**拿不到**未来数据，而非看不见。

## 六、风险备忘

- **gbbq 解密正确性**为新增关键项：按 pytdx 公开算法＋本机数据实测验证，不符则以通达信前复权显示值反推校准
- 前复权极端情形（超长历史＋高分红）可能出现非正价格：训练窗口内出现即提示并排除该股（v1 简化处理）
- tnf 名称偏移不固定：以本机文件实测校准，base.dbf 兜底
- klinecharts v10 自定义 overlay API 有学习成本：M3 预留调试余量
- 通达信运行中只读数据文件无冲突
- 不 fork 任何项目：pytdx/kfm_fqyz 仅参考格式与算法思路，klinecharts 按 Apache-2.0 集成
