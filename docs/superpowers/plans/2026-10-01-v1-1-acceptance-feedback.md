# V1.1.2 验收反馈整改计划

> 目标：处理 2026-10-01 用户对 V1.1.1 的 9 组批注，形成 V1.1.2 候选包。每组先保留失败回归，再实现最小行为切片；工程验收、用户验收和公开发布继续分开。

## 共同边界

- 通达信目录只读；测试使用独立 `TRAINER_DB`，不把用户当前 8787 数据库当夹具。
- 保留 T+1、整手 100 股、当日收盘成交、无未来行情和训练规则快照。
- 用户明确要求移除的成绩单 K 线复盘只移除当前 UI 入口和渲染，不删除历史画线或后端只读接口，待用户重新设计后再恢复。
- 行业排行只能使用可核验的 56 行业映射；无法证明归属时显示不可用/未分类，不猜测。
- 新增股票排行按代码精确分组，只比较相同股票的已结算训练；不与训练周期、行业视图混合。
- 交付只创建一个新的输出目录；不自动 push、tag 或发布 GitHub Release。

## 执行顺序

1. 建立本计划和任务状态；并行审计成绩单、排行/目录、设置/成交详情。
2. 先完成低耦合 P0：成绩单闪烁/复盘移除、代码名称修复、行业/股票排行合同、成交列表移除和浅色主题。
3. 再完成跨层 P1：成交笔记持久化、周期画线隔离、重新训练、画线偏好。
4. 每批运行定向 Vitest 与 `typecheck:web`；集成人运行 `npm run build`、`docs:check`、`docs:status -- --check`。
5. 用 Playwright/Edge 验证：成绩单、排行三模式、搜索 000602/000606、训练日/周/月画线、成交笔记固定、结算重新训练、设置和浅色主题。
6. 更新规格、任务卡、统一状态文件；只生成 `output/v1.1.2-<date>` 一个包，记录 manifest/SHA256，用户验收保持 `unknown`。
