# GLM派发工具：用量、额度与执行能力改进

2026-09-25，首批看板改进已实现并安装，工程验收见[GLM-MONITOR-02](../verification/2026-09/GLM-MONITOR-02.md)，用户验收待确认。本项不重开已关闭的ORCH阶段。

当前实施边界以[用量说明](../../scripts/agent-monitor/usage.md)为准：直接调用CLI原生`session/usage`，直接查询当前delegate使用的Coding Plan官方额度；Desktop独立活动套餐使用带原始时间的官方余额快照。没有本地token费用测算、余额反推或跨续接重复求和。下面的本地数据库聚合方案未采用。

本轮同时补齐new/resume、续接来源、附件信息及失败场景，保留两次backend尝试和集成人收尾记录。controller自动会话策略、多模态派发接线及2→3路产品试点仍是后续候选，不作为已交付能力；产品开发按实际任务需要使用现有显式`--resume`/`--attach`，不再追加架构阶段。

## 早期核查与候选方案

## 当前事实

安装的run_glm.py、monitor.py、telemetry.py和index.html与仓库副本一致。runner完成时将provider usage写入job，但monitor的输出白名单未包含usage，看板没有完整的累计token展示。监控数据库的model_usage表已有input/output/cache-read/cache-create/reasoning/provider-total、请求ID、重试序号、耗时等列，可以只读提取，不需要让模型估算。

本次抽查ORCH-03/04及真实试点共12个登记job，其中11个有已知sessionId且全部不同，附件计数为0。近期派发主要使用新会话；更早的ORCH-02定向修复脚本曾显式传--resume，故并非所有历史派发都新开。底层run_glm已有--resume和图片/视频--attach，但现有controller_runner未把会话复用或附件传到执行入口。新session也不代表没有公共提示、工作区规则、插件或模型端缓存。

上述11个已绑定工作树的会话，数据库记录247个已完成请求：输入22,943,329，输出391,632，缓存读取21,780,992，约占输入94.9%。这是多次请求累计值，不是单次上下文或唯一新增文本，更不是账单。部分超时job没有最终usage摘要，但它们的已完成请求有用量记录；只统计completed job会漏算。第12个未识别会话未强行补入，统计不是账户全量。

当前配置保持GLM-5.3-Flash、max思考档、1M上下文目标；不因增强利用率降低思考档，也不把本地配置值当作本轮真实上下文容量的证明。原始审计投影在本机控制层delegate-usage-audit.json和delegate-usage-detail.json，不包含凭据或模型思考全文。

## 余额为什么可能下降很慢

2026-09-25重新获取的[官方套餐概览](https://docs.bigmodel.cn/cn/coding-plan/overview)以每5小时/每周积分描述额度，并区分输入、缓存命中和输出的抵扣系数。页面还列出9月3日至10月7日23:00—次日09:00在ZCode等指定端调用GLM-5.3-Flash的夜间畅用活动，以及9月25日至10月7日全天非高峰抵扣活动。此前多批任务发生在夜间，加上较高缓存比例，可能解释余额变化较小；是否适用于本账户、CLI来源如何归类须以账户实测为准，不据公开页面直接断言本账户免费。

[ZCode使用统计](https://zcode.z.ai/cn/docs/usage-stats)明确区分本地会话应用用量与远端Coding Plan额度。旧页面仍有prompt池措辞，因此看板必须保留服务端单位和池类型，不硬编码为token余额。[配置说明](https://zcode.z.ai/cn/docs/configuration)中Coding与通用API端点也不能互换。用户已明确所指为zcode desktop中的Token Plan余额；本轮尚未读取该账户余额或确认它与当前delegate调用通道的对应关系。应先核实账户/供应商/套餐标识及原始余额单位，不能将Coding Plan活动、人民币API余额或其他供应商Token Plan规则直接套用。

已确认官方界面入口存在，尚未确认可供第三方稳定调用的公开quota API契约。接入前先核验ZCode使用的受支持只读统计能力和当前登录/套餐身份；无可靠数据时显示“未连接/暂不可读”和官方入口，不能用本地任务token反推远端剩余量。页面、活动和套餐数值具有时效，不能写死长期规则。

## 首批改进范围

### 1. 每个任务及整个任务链的用量

展示输入、输出、缓存读取、请求数、完成请求的耗时，以及逻辑任务所有尝试的累计值。失败/超时/取消已发生的请求照常计入，缺失值为未知而非0。缓存读取作为输入组成，不重复相加；provider未报告的reasoning字段不冒充已测0。

按job→session→request/attempt绑定数据库记录。续聊时记录会话起始高水位或明确turn/request集合，不能把整段旧会话累计值再次归入新job；重试必须保留实际发生的调用，不按logical_request_id把已计费重试去掉。最终摘要与数据库是同一用量的两个来源，应对账/选择，不能相加。

本地界面可每5秒更新已收到的usage。进行中请求尚未返回usage时展示“等待本次用量”，必要估计要另列，不能把准实时累计包装为逐token精确计费。数据显示来源、最后更新时间及覆盖完整度。

### 2. 独立的账户额度栏

单列zcode desktop所显示的Token Plan账户/套餐别名、额度池、服务端原始单位、已用/剩余/比例、重置时间、活动说明、获取时间和新鲜度。先验证desktop和delegate CLI使用同一账户及额度池；若不同应明确显示“当前任务不使用此额度池”，不能用两个数的变化推算消耗。账户额度可能被同池的其他客户端共享，不能将其归属到一个task。

只有受支持并已核验的只读来源才显示余额。建议默认60秒缓存刷新、手动刷新去抖；页面仍5秒读本地快照，避免多个标签对远端重复请求。接口限频时退避，断开保留带时间戳的旧值并明确过期。不自动购额、重置权益或切换账户。凭据不进页面、Prompt、仓库和可分享日志。

### 3. 明确会话与能力合同

在现有delegate入口增加明确的session_mode=new/resume/auto、resume_session_id，以及经过校验的attachments和允许的浏览器能力。新独立目标默认new；同一任务的小范围修复、设计未变且前一进程已结束时优先resume。换基线/工作树、过长或混乱上下文、原假设失效时新会话接精简证据。会话变化不清零逻辑任务尝试、token和repair计数。

附件应随任务传递：图表问题给前后截图和期望标注，交互问题给短录屏、复现步骤、浏览器错误和DOM事实。GLM可做视觉侦查、候选UI实现、自查与定向修复；模型视觉判断不能替代真实点击、几何断言、控制台检查及已有高风险验收。底层attach支持已存在，controller接线和实际浏览器能力仍需有界验证。

## 更充分使用GLM的方式

目标用“每小时通过验收的产品切片”和“每次合格交付需要的强模型介入”衡量。用户的额度充足可用于并行侦查、完整行为实现、独立反例检查及视觉自查。优先在当前已验证的2路基础上试3路不同职责/工作树；4路只在官方账户允许、无持续429且本机测试资源可承受时试用。写权限、共享文件和测试资源仍须隔离，不能因为配额充足同时写同一API文件。

避免把GLM固定当成只写纯函数的执行器：对已冻结接口的任务，让它负责API、页面、测试和交接的一整个可验收行为切片。明确主工作区已有FRESH-01/RANGE-01及当前提交，避免再次重建已完成模块。强模型主要处理合同变化、持续未知、高风险不变量和最终产品语义。

当前max模式部分请求曾持续数分钟，GLM的模型速度与完整工程任务交付速度要分别观察。看板增加运行阶段：读取/模型请求/工具执行/测试/报告/待验收，分别显示阶段时长。总时限与无活动时限分开；有明确进展的测试或请求不当作死锁。先提供接近预算时的检查点和有限宽限，硬超时仍保留产物与请求用量，不能无限延长或原样反复重启。

## 实施与验收顺序

1. 先交付本地用量和任务链统计：数据库只读、失败用量、resume不双计、缓存不双计及缺失为未知的回归；看板真实展示与隐藏页面刷新检查。
2. 并行核验套餐读接口；确认数据源后接额度栏，未确认时只给明确的未连接状态和官方入口。用同一账户界面在接近同一时刻对照剩余/重置信息，不仅做模拟JSON测试。
3. 接通session策略和attachments，做一个真实新会话任务、一次同任务resume及一个图表截图/短视频任务；验证模型收到附件，并运行真实行为验收。
4. 用DATA-05/ TRAIN-02接线试跑2→3路职责分离，记录错误率、等待、完成率和强模型介入。先完成这批小改进，再继续产品主线，不扩建新的调度平台。

本方案未改变现有runner或看板代码，未调用付费模型做“耗额测试”，未读取账户凭据。用户确认目标余额来自zcode desktop的Token Plan，并希望更充分使用GLM的能力和可用额度；具体账户与派发通道绑定及套餐只读数据来源仍需核对。
