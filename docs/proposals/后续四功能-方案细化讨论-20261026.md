# 后续四功能·方案细化讨论（2026-10-26）

> 定位：讨论稿（proposal），非开发计划。目标是把四个目标功能各自的方案空间、开源实践、隐藏坑（unknown unknowns）与拍板项摊开，供逐个深入讨论后立项。
> 现状基线：v1.3.3（Electron＋Fastify＋SQLite＋Vue＋klinecharts v10），单仓单树。

## 拍板记录（2026-10-26 用户）

**执行顺序（调整后，依据用户调研的功能呼声序＋3060 不在身边的现实约束）**：

> 回放收藏分类 → K 线多空反转 → 公式系统 → P2P 联机切磋

- 呼声序本身为 联机>收藏>公式>反转；因暂无法启动 3060 辅助联机开发验证，联机后移至最后。两张低成本验证卡（TECH-P2P-PROBE／TECH-FORMULA-RECON）随各功能正式开工时再执行，不提前。

**回放收藏分类（已定设计）**：
- 存储按推荐方案 A：物理目录平铺＋SQLite 收藏索引（多对多），支持自建目录。
- 训练器自带一个内置「收藏」目录（不叫"我的最爱"，作用相同），条目上的星星按钮（参照 QQ 邮箱邮件条目星标交互）即快速加入/移出该内置收藏目录；内置目录用星星标志与用户自建目录区分，不可删除。
- 导出（REC-BULK）统一保留收藏结构。

**联机切磋（已定设计要点，实现排最后）**：
- 开房流程：房主选定模式并填好信息（经典模式＝选股票＋时间段；随机模式＝选定随机项目）→ 开房生成邀请码 → 受邀者凭码加入后**直接进入模拟训练正式开始的页面**；双方都必须已安装 K 线训练器才能继续。不提供语音聊天（房主自行用即时聊天/语音软件）。
- 对战界面复用当前训练模式的界面；主页面左侧己方头像、右侧对手头像。
- 趣味互动：免费趣味道具＋交互动画（丢番茄、丢鸡蛋、点赞、比心、戴墨镜等，类似抖音直播特效礼物）。
- **推进模式＝回合同步推进**（只做同步推进，不做自由节奏）：双方都同意进入下一根 K 线才推进，先完成者等待。
- 同步模型按推荐：各自独立模拟＋事件共享（主机统一下发该局行情数据）。
- 持仓与划线不对对方可见。
- 观战席位：房主设定观战人数上限，观战者凭**观战专用邀请码**进入。
- PK 结束后弹提示：是否保留双方回放录像——保留双方／保留一方／都不保留；保留的录像进入**专属 PK 回放目录**（内置收藏）。

**公式系统（已定方向）**：
- 以**功能全面性**为主要目标；兼容通达信公式代码语法，在已有开源基础上二次开发补足——**不能把 formula-ts 等既有实现的限制带进产品**。
- **未来函数要支持**，通过显式标记提示（不禁止）。
- 跨周期引用（#WEEK 等）formula-ts 不支持则**另行探索方案实现**，功能性必须强大全面。

**K 线多空反转**：按本文第四节建议开发（视图层镜像＋水印防混淆＋训练/回放页可用、不影响交易结算）。

## 一、联机切磋模式（P2P 开房 PK）

**目标**：与好友开同一房、练同一题（同股票同区间同起点），实时或事后比对，对齐颗粒度共同精进。

### 现有架构契合点
- 训练引擎是确定性的（同数据＋同操作＝同结果），天然适合"各自模拟＋比对结果"。
- 随机模式（M7）已实现会话级数据变换与隐藏/揭示，联机的数据下发可复用其管道思想。
- 日线数据体量极小（250 根 OHLCV ≈ 几十 KB），P2P 秒级传完。

### 开源/行业实践（调研结论）
- WebRTC DataChannel：浏览器/Electron 原生 P2P 数据通道；训练是回合制推进，用可靠有序模式即可，无需 UDP 快速模式。
- **P2P ≠ 零基础设施**，两个隐藏依赖：
  1. **信令交换**（建连前互换 offer/answer）：可手工复制粘贴邀请码（真正零服务器，微信里发一下即可）；或用 PeerJS 免费公共信令；或自建极小信令服务。
  2. **NAT 穿透**：Google 公共 STUN 免费覆盖大部分场景；对称型严格 NAT（经验值约 10~15%）需 TURN 中继（自建 coturn 或明确不支持、退化为同局域网）。
- 参考：pion（信令＋STUN 同机部署实践）、多个零服务器 WebRTC 小游戏先例（手工信令可行）。

### 方案空间与推荐
- **同步模型（核心拍板）**：
  - A（推荐 MVP）**各自独立模拟＋事件共享**：主机生成训练配置（股票/区间/初始资金）并把**该区间行情数据整体下发给客机**；双方本地各跑现有引擎，DataChannel 只广播轻量事件（推进/下单/结算），前端叠加对方权益曲线。复用全部现有引擎与 UI；断线各自可继续；朋友局无需防作弊。
  - B 主机权威模拟：客机只发操作收状态。复杂度高、断线即死，不推荐。
- **数据一致性（关键坑）**：行情必须由主机统一下发，**不能各自读本地通达信**——复权因子随时间变化、本地数据新鲜度不同，两边 K 线可能不一致，PK 就失真了。主机下发一份数据即根治（顺带解决"朋友没装通达信"）。
- **邀请机制**：MVP 用手工交换邀请码（SDP 压缩）；体验优化再考虑房间码＋免费信令。
- 版本握手：开房时互报训练器版本，主版本不一致拒绝并提示升级。

### Unknown unknowns（提前摊开）
1. SDP 邀请码较长，手工交换体验一般——压缩＋一键复制/粘贴引导；同局域网场景 mDNS 直连体验最好。
2. **推进节奏**：同步推进（谁慢等谁，切磋感强但互相拖）vs 自由节奏（各练各的最后比分）。建议 MVP=同题各自练＋结算比分板，V2 再做回合同步。
3. 中国家宽 NAT 严格程度分布无公开可靠数据，**连通率必须真机样本验证**（3060＋好友机各网络环境各试一轮）。
4. 不做 TURN 时部分用户会连不上——UI 要预设预期（"直连失败请换网络或同局域网"）。
5. 对方持仓/画线可见性涉及隐私偏好——做成开关（默认只比分不见持仓）。

### 拍板项
- 邀请机制（手工码 / 免费信令 / 自建）
- 同步模型与 MVP 范围
- 比分板指标集（收益率/最大回撤/胜率/操作数？）
- 是否允许观战、第三人参战人数上限

### 建议阶段
- M8a MVP：手工邀请＋主机下发数据＋同题各自练＋结算比分板
- M8b：回合同步推进、对方持仓可见性开关
- M8c：房间码＋信令服务器化，TURN 兜底评估

## 二、训练回放收藏与分类

**目标**：用户自建目录（"骑牛1买训练""自选股训练"…）分类管理录像，快速调取复盘。

### 现有架构契合点
- DATA-ARCH-01 已自动归档至 `<dataDir>/recordings/` 且语义化命名；录像库页已有导入/历史/回放；REC-BULK 交换包成熟。

### 方案空间与推荐
- 存储：A（推荐）**物理目录保持平铺＋SQLite 收藏索引**（collections 表＋录像↔收藏多对多）。不破坏自动归档与导入路径；一盘可属多个分类（"骑牛1买"＋"自选股"双归属）；迁移零成本。B 物理子目录——直观但破坏导入路径与既有索引，一盘只能一个目录，不推荐。
- UI：录像库左侧目录树＋拖拽归档＋星标；按股票/模式/日期/成绩筛选。
- 分享：收藏夹整体导出为 REC-BULK 包（复用现有导入）——与联机功能联动（切磋后的复盘素材交换）。

### Unknown unknowns
1. 录像被删后索引引用悬空——级联清理。
2. 旧导入录像（v1.2.7 等）也要能归类——索引对象用会话 ID 而非文件名。
3. 收藏夹嵌套深度与重名约束。

### 拍板项
默认"我的最爱"收藏夹是否要；导出包是否携带收藏结构；UI 树 vs 页签。

### 建议阶段
单任务卡（小）。建议排在联机 MVP 前后作填隙。

## 三、公式系统（自定义指标＋选股）

**目标**：训练器内自定义主/副图指标与选股公式，复用通达信语法资产。

### 调研结论（改变方案空间的关键发现）
- **[formula-ts](https://github.com/DTrader-store/formula-ts)（MIT，TypeScript，npm `@dtrader/formula-ts`）**：通达信语法解析器＋执行引擎。公式→AST；输入 OHLCV 输出输出线/中间变量/绘图事件（DRAWTEXT/STICKLINE 等）；支持增量计算；有完整测试体系。**与训练器技术栈完全同构**。
- 限制：极早期（8 star／29 commits）；**无跨周期引用（#WEEK/#MONTH）**；未来函数（ZIG/BACKSET）未处理；部分函数行为待核。
- 周边可参考：[formula-go](https://github.com/DTrader-store/formula-go)（Go 同类）、通达信函数文档 VS Code 插件、通达信公式→ClickHouse 全市场回测方案（选股性能参考）。
- 国际范式：TradingView Pine Script——series 语义、**防未来函数是一等公民**、命名输出。DSL 设计上值得借鉴其"防未来"哲学。

### 方案空间与推荐
- **语法（核心拍板）**：A（强烈推荐）**通达信兼容子集**——直接复用存量公式资产（骑牛买1/2/3、万能过左峰、分金定穴……这是本功能对本项目的最大价值）；语法本质是表达式＋系列函数，解析可控；现代化扩展（参数区/命名输出）以不破坏兼容为前提叠加。B 全新语法（Pine 风）——存量公式全部重写，价值大损，不推荐。
- **引擎**：A（推荐）以 formula-ts 为内核＋**适配审查**（本工程铁律：复用开源先对拍口径）。函数逐个对拍通达信——**本工作区就有现成 oracle**：《通达信函数速查表.md》（877 行）＋《通达信选股公式实战案例.md》（50+ 案例）＋用户在用公式，据此建 conformance 测试套件（每函数至少 3 例），不符则修内核或从子集白名单剔除。B 完全自研解析器——工作量数倍，仅当 formula-ts 评估不合格时启用。

### Unknown unknowns（本功能最大的坑都在这）
1. **未来函数**（ZIG/BACKSET/FILTER）：训练是逐根推进的场景，未来函数会"重绘"——训练器里必须禁用或显式标记（候选矩阵行：FORMULA-FUTURE-FUNC-GUARD）。通达信里这靠口头知识，工程化是差异化价值。
2. **跨周期引用**：用户公式大量使用 `#WEEK/#MONTH`（骑牛买1 周月共振），formula-ts 不支持——需自实现周期重采样＋引用（周线聚合本工作区已有先例：tdx_sector_rank 的自然周聚合），或 MVP 声明不支持列为 P1。**这直接影响"存量公式能否直接用"**，建议早期专项评估。
3. 复权口径：训练器前复权数据与用户通达信看盘口径一致即可，但公式计算结果要与其通达信里对得上（对拍时注意）。
4. 选股性能：全市场 5000+×公式——MVP 先限定池（自选/板块/指数成分），全市场后置（ClickHouse 案例参考）。
5. 绘图事件渲染：formula-ts 只出结构化事件，需自写 klinecharts v10 overlay 渲染层（训练器自定义指标 API 已在用，可行）。
6. 安全：AST 解释执行、不 eval、不起子进程——天然沙箱；限制解释深度/循环防死循环卡服务端。

### 拍板项
- 子集白名单范围（建议：以用户在用公式反推必需函数集，速查表全量后置）
- 跨周期引用是否进 MVP（强烈建议早期做技术验证卡，它决定价值兑现度）
- 选股入口形态（公式选股→"用结果开一局训练"一键联动？）

### 建议阶段
- M9a 引擎适配＋conformance 测试套件（纯后端无 UI）
- M9b 副图自定义指标（贴训练图表）
- M9c 主图指标＋绘图事件渲染
- M9d 公式选股→开训练联动（与联机、收藏串成闭环：选股→训练→PK→归档）

## 四、K 线多空反转（空头视角）

**目标**：把 K 线图镜像翻转，从空头视角检验多头判断（翻转后仍"看涨"才客观）。纯分析辅助，不提供做空。

### 调研结论（一个澄清性发现）
- 搜索未找到同花顺官方"多空反转"功能文档；**同花顺手机版目前没有原生翻转 K 线功能**（可设的只有 K 线样式与多空指标叠加）。国际通行做法是 **TradingView Invert Scale**（反转价格轴，Alt+I）与 MT5 翻转指标，用于消除交易偏向。
- 这反而说明：**A 股桌面/训练工具里这是空白**——训练器做它有差异化价值。

### 方案空间与推荐
- 变换层设计（推荐）：视图层开关，K 线数据镜像 `p′ = 2×P₀ − p`（绕首根收盘价翻转，保持正值域），开高低收全镜像（阳线形状变阴线形状）；指标用镜像序列重算（MACD 翻转到水下，正好练"黄白线水下"的空头语感）。
- 备选 B：只反转价格轴不镜像蜡烛形状（TradingView 原样）——镜像感弱，训练价值打折。
- 防混淆三件套：开启时显眼水印「多空反转视角」、开关态高亮、回放页同步适配。
- 范围：训练页＋回放页；**不影响交易与结算**（纯视图）；与随机模式、既有画线兼容（画线价格坐标跟随镜像）。

### Unknown unknowns
1. 镜像价数值无实义——坐标轴显示镜像价＋水印提示，或辅助显示"−涨幅%"轴，需试用定夺。
2. 用户既有画线/均线跟随镜像（不跟随会造成视角混乱）。
3. 说明文案要防误导：这是"多头分析之镜"，不是做空信号（用户已明确）。

### 拍板项
镜像基准（首根收盘价 vs 区间中点）；坐标轴呈现方式；指标副图是否默认同步镜像。

### 建议阶段
单任务卡（小）：变换纯函数＋视图开关＋回放适配。快赢，可穿插任何批次。
