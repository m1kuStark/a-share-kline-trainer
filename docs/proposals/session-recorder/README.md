# 操作录像机与自动验收

本目录保存设计资料，实际实施状态见[REC-01](../../work-items/tasks/REC-01.md)。首批录制/回放正在功能分支开发；2026-09-19新增紧凑存储评估，尚未实施格式迁移。目标是让Agent理解用户每一步、复现问题，并让训练器加载记录复盘。

建议记录**语义操作、实际结果和必要的界面轨迹**。视频适合看现象，结构化记录适合回放和断言；可附截图/视频，核心文件仍为可读JSON。

- [格式与记录边界](format.md)：版本、数据、状态、事件与异步结果。
- [接入与验收设计](implementation.md)：现有入口、三种回放、computer use和分批实现。
- [简化示例](example.json)：只展示结构，不是可导入的正式版本或有效验收夹具。
- [紧凑存储建议](compact-storage.md)：按实际体积评估的版本增量、轻量检查点与压缩方案，尚未接入生产。

## 已确认的产品方向

用户已确认录制默认开启，首页和训练中可切换，训练中持续显示记录状态；用于测试、找bug、个人复盘和用户间分享，作为正式用户功能。现行要求见[录制规格](../../specs/recording.md)，实现和验收分别由任务卡及证据记录。

暂停与恢复要明确标记未录区间，恢复时保存新checkpoint；分享包携带所需数据和规则，接收者在隔离会话查看，不依赖原用户本机路径。

## 记录范围

“全部操作”应覆盖开始训练、交易、推进、切换周期、视窗、图形创建/编辑/拖动/删除、撤销/重做、文本确认/取消、主题和结束训练；拒单、未完成绘图、加载失败及操作被守卫阻止也要记录。跨操作系统的其他应用操作不在训练器记录范围。

不默认逐帧记录每次鼠标移动。普通操作保存最终语义；拖拽、吸附等问题可开启详细输入轨迹。这样文件可读、体积可控，回放也不依赖某台电脑的固定像素。

## 能减少哪些人工工作

用户报告问题时导出一次记录，Agent定位失败步并生成回归；提交前自动跑固定训练旅程和历史问题库，附结果差异及截图。用户主要评估新交互、视觉偏好及产品规则，无需每次重走整套训练。

现有Playwright已能真实点击、按键、绘图及交易。还需稳定的控件语义、图表坐标映射、可观察的加载/保存/忙碌状态和完成信号。Canvas无法仅靠DOM表达所有几何，保留只读坐标投影辅助；不得通过写内部状态冒充真人交互通过。

严格可重复性依赖[DATA-03](../../work-items/tasks/DATA-03.md)历史数据及[TRAIN-01](../../work-items/tasks/TRAIN-01.md)规则冻结。当前录制可以先做，但缺少依赖时只能声明“按记录展示”或“当前数据下重试”，不能声明精确复现。
