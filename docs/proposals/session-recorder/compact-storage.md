# 紧凑录制方案：操作、数据版本与恢复锚点

状态：2026-09-19评估建议，尚未接入生产；不改变当前schemaVersion=1合同。用户要求先说明体积原因和解决方案，不恢复已撤回的自动停录开发。实验与复原证据见[压缩评估](../../verification/2026-09/REC-01-compression/report.md)。

## 问题与选择

120次推进的27.45MiB中，98.58%是重复bars。当前finish(chart.load)和capture各写一次全行情，每份1040根；Recorder在每次保存时又复制、写入累计会话。gzip只能缩小最终文件，不能消除录制期的这些复制和写入。

推荐逻辑结构：**语义操作＋只保存一次的必要数据＋变化记录＋轻量恢复锚点**。分享默认可采用gzip封装JSON，调试时保留可读JSON导出；不引入自动停录。正式采用结构变化时使用schemaVersion=2，v1导入保留显式兼容路径，不能把两种结构都标成v1。

## 每类内容怎样保存

| 内容 | 保存方式 |
|---|---|
| 版本、股票、训练参数、数据单位 | 会话头一次保存；规则改变时增加观察版本 |
| 用户操作 | 推进、买卖、周期、绘图等语义事件；保留实际结果、失败原因和配对关系 |
| 行情 | 首次所需历史一次保存；之后保存新增/替换/移除记录，图表状态引用相应版本 |
| 画线 | 对象ID、工具类型、窗格、日期/价格锚点、样式/文本；按创建、更新、删除记录变化 |
| 账户与成交 | 保存实际观察到的结果；未变化账户不重复，成交仅追加新增项，不按操作意图重新成交 |
| 图表状态 | 当前周期、可见日期、柱宽、窗格高度等小状态；手势结束存终态，普通模式不存每个鼠标像素 |
| 恢复锚点 | 初始、暂停恢复、关键结果及定期锚点；指向数据版本和对象状态，不重复内嵌大数组 |

普通线段的两个日期/价格点足以确定几何，但还需要工具类型来区分线段/射线/直线；多点折线和文字保留各自点集和文本。实验中的含ID、窗格和线型的两点线段只有214字节；不需要图片来保存它。

started/finished是诊断异步请求的配对信息，本次测量的480条事件合计约107KiB，暂不以删除错误/请求结果节省这部分。后续可以把基础设施事件归入诊断区，用户操作列表保持清楚。

## 行情必须保留当时版本

复权会改变此前日期的OHLC，周/月未收盘柱每天也会变化；不能把date作为唯一键，用最终行情覆盖历史录制。建议按`股票＋周期＋完整Bar内容`识别相同值：内容相同复用，内容变化生成新版本。

示意，字段名仍待正式合同确定：

```json
{
  "format": "trainer-session",
  "schemaVersion": 2,
  "marketVersions": [
    {"id":"daily-1","asOf":"2025-01-02","bars":"首次观察到的完整必要行情"},
    {"id":"daily-2","base":"daily-1","asOf":"2025-01-03","upsert":"新增或实际变化的K线","removeDates":[]}
  ],
  "events": [{"seq":1,"action":"training.advance","outcome":"accepted","resultRef":"state-2"}],
  "checkpoints": [{"afterSeq":1,"marketRef":"daily-2","accountRef":"account-1","drawingRef":"drawings-1"}]
}
```

这里只解释关系，字符串占位不是真实Bar结构或可导入文件。引用全部指向文件内数据，不依赖本地TDX路径。每一步只能取得该步引用的可见版本；整个分享包最多携带发送方已经看到的范围。

增量链不能无限延长。实验每32个行情版本保留一次完整基础，变更比全量大时也保存新基础；此数字是试验参数，正式值由两年场景的随机跳转/恢复性能决定。除权日可以整体更换观察值，不靠未来版本的复权算法重新计算历史。

## 录制期和导出期一起改

浏览器IndexedDB拆为会话元信息、追加事件、不可变数据版本、轻量状态四类记录，同一个事务提交一批相关事件/版本与恢复游标。每次只写增量；失败/刷新不能留下引用不存在的数据。

相同chart.load结果与随后的capture只生成一个内容状态，事件仍分别保留必要结果；相同内容可有多个时间引用。事件与检查点的时间先后不能靠内容去重抹掉，禁止把未来状态绑定到更早的seq。

回放只重建正在显示的图表版本，缓存数量有界。不能导入后先展开所有历史完整快照，否则分享文件虽小，内存仍回到原来的巨大重复量。

导出最后再gzip压缩JSON。文件扩展名、压缩封装版本和JSON schema分别明确；导入分别限制压缩体积、解压体积、结构数量和引用复杂度。原25MiB不能直接照搬为所有层同一门槛，应由正常两年样本及浏览器实测校准；这不等同于给用户训练自动停录。

## 可交给GLM的后续小任务

1. 冻结v2逻辑合同与旧版兼容用例；复用这次数据集明确不前窥、真实结果和缺口语义。
2. 纯行情版本编解码：同内容复用、增量/基础选择、跨除权/周月变化；逐步深度相等验证。
3. 录制写入与IndexedDB增量事务：移除整会话重复克隆写入，恢复游标和错误重试回归。
4. 导出压缩、受限导入、回放按需重建；两年正常训练与有交易/画线场景的浏览器验收。

开始上述实现前先依据本方案更新任务和共享合同。验收看数据一致、正常两年完整导出/导入、保存和跳转性能；不以某个压缩比例替代正确性。当前实验不证明真实浏览器峰值内存、IndexedDB耗时和所有股票/画图复杂度。
