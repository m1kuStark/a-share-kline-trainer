# 接入与验收

## 三种回放分别证明什么

| 模式 | 执行方式 | 能证明 |
|---|---|---|
| 复盘展示 | 读取记录中的结果和checkpoints，暂停/跳步/倍速 | 用户当时做了什么、当时结果是什么；不证明现代码仍正确 |
| 业务重放 | 对相同规则/数据快照重新执行语义命令，比较账户和状态 | 交易、推进、权息、持久化计算是否回归 |
| 真实UI回放 | Agent/Playwright按控件和图表映射做真实鼠标键盘操作，等待完成再比较结果 | 按钮、热键、焦点、弹窗、绘图、布局和业务链路能否走通 |

精确指针问题可在原viewport/DPR模式回放，跨尺寸按时间/价格投影；两者必须标明。等待“交易完成/图表数据版本稳定/保存确认”，不依赖固定sleep。比较账户、图形、视窗、状态以及关键视觉截图；截图像素差异仅作视觉信号，数值判断需要独立断言。

## 当前接入点

- `KlineChart.vue` 的recordDrawings/onDrawEnd/onPressedMoveEnd：完整画线状态、动作与坐标；新增开始/取消等未完成过程。

逐步建立类型化的命令入口/事件订阅点，避免到处插console.log；采集层与控制层分开，回放时标记来源以防再次录入形成循环。现有SQL只有流水和最新图形，无法补回过去全部交互；旧训练只能从现有状态开始录制，不能伪造历史操作。

## computer use友好表面

DOM控件使用稳定role/label、焦点和disabled/busy状态；关键步骤有可观察的结果说明。测试构建提供只读图表坐标投影、pane bounds、当前周期、数据/保存revision。Agent能根据页面和记录定位目标；写操作仍通过公共业务入口或真实UI，UI测试禁止直接恢复内部图形代替绘图。

Canvas可增加键盘选工具、对象清单、选中对象语义和价格编辑面板，提升可访问性，也让Agent可靠定位。不要为了自动化给正式用户界面加入开发术语或隐藏写后门。生产录制可以存在；调试只读hooks和测试控制能力独立开关。

## 分批推进

1. 定schema与操作目录，做录制开关、追加日志、崩溃恢复、JSON导出和AI可读摘要；验收买/卖/拒单/推进、三周期、创建拖动编辑删除/撤销图形。
2. 做加载、校验、只读复盘和checkpoint跳转；能还原记录中的结果，明确不重新成交。
3. 完成规则/数据冻结和命令幂等，再做业务确定性重放及状态差异报告。
4. 将记录转换成真实UI步骤，纳入现有独立运行目录和候选门禁；历史bug记录成为回归案例库，保留首次失败trace和截图。

建议第一版默认录语义和结果，详细轨迹按需；导出自包含样本包优先用于本地调试，分享时检查数据权限及去标识；后台不无限保存鼠标轨迹。录像机不替代基础单测和独立手算对账，避免记录与回放共用同一个错误而互相“验证通过”。

尚需讨论：默认是否开启录制、长会话保留期限、第一版导出是否携带完整行情快照、详细轨迹开关。建议默认在测试模式开启，日常由用户一键开启；先做基础复盘，再接严格自动回归。
