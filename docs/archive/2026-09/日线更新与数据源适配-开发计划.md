# 日线更新与数据源适配 · 开发计划

> 2026-09-16 新增需求。本文件是本批任务的范围与验收依据。
> 顺序：R0 数据保护 → R1 本地更新与适配边界 → M4/M5 → R2 真实替代来源。总计划见 [开发计划](../../开发计划.md)。
>
> **执行状态（2026-09-17 复核，待用户验收）**：R0 等待守卫、目录失败保护和 R1 扫描协调器、双页面更新入口、启动/激活状态检查已有实现和测试。**R0/R1 尚未满足全部计划要求**：目录/权息/文件快照分开提交；结算仍用全市场末日推断个股停牌；历史修订仅按文件元数据检测＋警示，未保存可读取旧版；env/stocks 独立刷新入口未迁移。首扫保存的是文件状态基线，不能称为旧行情保护副本。详细差距见 [当前状态 DATA-01～04](../../status.md)。§5 现有合约只覆盖扫描；训练仍直接依赖 TDX，R2 真实在线源未接入。以下复选项作为验收目标保留，不以现有单测通过代替整批完成。

## 1. 用户能得到什么

首页与训练主页面都可以点击“更新日线”。应用启动、窗口重新激活时自动检查本地变化，用户不必重新打开训练器。结果说明检查时间、更新数量、来源及当前股票的数据日期；没有新数据和读取失败分别提示。

首版来源仍是通达信已下载的离线文件，只读扫描与同步，不代替通达信联网下载。后续在线来源接到同一按钮及自动检查流程，用户无需安装通达信。

## 2. 实施前能力与原计划动作（2026-09-16）

本节保留需求提出时的起点；当前实现以页首状态注及状态页为准。

| 项目 | 现状 | 本批动作 |
|---|---|---|
| 本地行情 | 请求时直接读 `.day`，并非数据库缓存全量行情 | 复用解析能力，增加稳定读取与版本边界 |
| 股票目录/权息 | `/api/env` 隐式刷新两者；stocks 请求扫描目录；各自有进行中请求合并 | 抽出统一服务；状态读取不重复触发全量扫描 |
| 当前图表按钮 | “刷新图表”重新调用当前训练行情；“回到最新”重置视图 | 保留语义，与“更新日线”区分，避免同名入口 |
| 日期 | env 为全市场最大日期，App 挂载时读取 | 更新后同步两页状态，单独显示个股末日 |
| 推进到数据尾 | 无下一根就按正常到期结算 | R0 区分等待数据与真正到期 |
| 源目录读取失败 | catalog 将 readdir 错误转为空列表，可能删除既有目录缓存 | R0 失败保留上次有效目录，不把不可读当空目录 |
| 历史修订 | 外部行情随时可变，训练无来源版本快照 | R0/R1 检测修订并隔离，完整复现能力仍须补齐 |

关键入口：`server/src/api.ts`、`tdx/catalog.ts`、`tdx/dayfile.ts`、`tdx/adjustment-cache.ts`、`train/engine.ts`、`db.ts`；前端 `App.vue`、`api.ts`、`views/Launcher.vue`、`views/Training.vue`。实现可新增 `server/src/data/` 与共享前端状态模块，不将来源判断散落到图表组件。

## 3. R0：先补数据保护

- [ ] **等待数据**：找不到下一根时，必须同时确认来源覆盖至计划结束，以及缺线区间确属非交易日/停牌等正常缺线，才能正常结算。日历只能说明开市日，结束日后有记录只能说明源尾覆盖，二者单独均不能证明个股中间没有漏数。TDX缺少可靠完整性或停牌依据时保守等待，仍为running，返回“等待日线数据”原因，保留当前日并允许更新后继续或用户提前结算。
- [ ] **结算边界**：末日恰为计划结束、结束日在周末/节假日、个股停牌、源数据缺口、结束日后有记录但中间漏数分别建样例；不以系统日期或全市场最大日期单独证明个股数据完整。用户仍可主动提前结算。
- [ ] **旧成绩兼容**：既有 settled 训练保持原终点，不自动重开、延长或重算；M4 对因历史数据不足而结束的记录另行识别/标记，不擅自判为完整周期。
- [ ] **目录失败保护**：断盘、权限错误、文件消失、单市场读取失败须报告并保留上次成功目录；确实不存在的可选市场与曾存在但暂不可读区分。删除缓存只能依据成功且完整的扫描。
- [ ] **稳定读取**：TDX 下载过程中发生半条记录、长度/修改时间变化等，不发布混合数据。目录元信息与记录来自同一份稳定字节内容；校验失败可有限重试，继续失败保留旧版。
- [ ] **一致性发布**：先准备及校验目录、日线变化、权息，再提交训练器侧版本；不能日线成功、权息失败却显示“全部更新成功”。不把异步文件读取放在长期占用 SQLite 写锁的事务中。
- [ ] **历史修订策略落地**：区分纯追加、已有日期/OHLC/成交量/成交额改写或删除、既往权息修订。R0/R1就把稳定原始字节或标准化记录及指纹保存到训练器自有存储，已有训练依赖旧版时继续可读；不能等R2再补缓存。影响旧训练的修订不得静默替换，无法恢复旧版时阻止按混合口径推进并报告。
- [ ] **旧训练迁移起点**：首次启用保存当前稳定文件及权息作为“迁移后保护基线”，以后才据此检测变更；不宣称恢复了训练创建时的数据版本。旧流水/当前收盘价与此基线不一致时标记待核对，保留原流水，不自动重算账户。

R0 是自动检查上线前的必要条件。不能仅加定时扫描放大现有边界问题。

## 4. R1：更新服务、按钮、自动检查

### 4.1 统一更新服务（接口草案）

- [ ] 新建统一刷新协调器，手动、启动、窗口激活和内部调用共用；同一来源同时只运行一个任务，多窗口/重复点击复用该任务。
- [ ] 候选 API：`POST /api/data/refresh` 启动或复用任务；`GET /api/data/status` 读取状态及最近结果。前者返回任务标识和当前状态，后者不重复扫描文件。
- [ ] 状态区分 idle/running/unchanged/updated/failed，成功结果带来源、开始/结束时间、修订标识、扫描/新增/修改/移除数量、来源最大日线日期、请求个股末日；失败带可行动原因和上次成功状态。不能推算不可靠的精确进度。
- [ ] env 保持旧客户端兼容；迁移其隐式扫描职责，stocks 查询避免每次搜索都全盘扫描。创建/推进在消费新数据前必须获得匹配的权息版本，不能依赖此前偶然的 GET 请求完成同步。
- [ ] 对任务超时、服务重启、来源失联进行恢复；失败不清空已有训练页或有效缓存，错误不能被“已是最新”覆盖。

### 4.2 两处按钮与信息展示

- [ ] 首页放在数据状态附近；训练页放入现有紧凑操作栏。使用相同“更新日线”文案、图标、loading 和结果状态。
- [ ] 首页显示来源及来源日线最大日期；选股后给个股末日。训练页常驻推进日，个股数据末日/最近检查时间可放详情，避免额外占据整行。
- [ ] 更新结果不抢焦点、不弹模态确认；固定状态占位，深浅主题可读。详细原因可展开；失败提供重试。
- [ ] 无变化不重建图表；纯追加且全部晚于推进日，仅更新来源状态。需要重新读取当前图表时仍按训练日截断，并保持周期、缩放、视窗锚点、副图高度和选择状态。
- [ ] 未完成绘图或存在待保存副本时，图表更新延后到安全时点；不得丢弃草稿、清空撤销历史或用旧请求覆盖新画线。交易/推进与刷新不能读到半个版本。
- [ ] 用户在历史位置看盘时，更新不把视图拉回最右；“回到最新 K 线”仍由用户显式操作，且“最新”指该训练可见范围。

### 4.3 自动检查默认策略

- [ ] 应用启动检查一次；窗口从后台回到前台时，距上次检查至少 60 秒才触发（首版实现默认值，可通过后续设置调整）。同一次激活的 focus/visibility 事件合并。
- [ ] 手动点击绕过上述时间节流，但复用正在运行的任务；隐藏页面不轮询，不创建系统计划任务。
- [ ] 自动无变化保持安静；更新成功用轻量状态提示，失败保留可重试状态。不推进行情、不下载未授权服务商数据。
- [ ] M5 提供自动检查开关和偏好持久化。持续周期轮询、盘后定时下载另行按真实来源能力规划。

## 5. R1/R2：数据源边界

R1 先定义以下合约并包装 TDX；用测试假来源验证训练引擎不直接依赖 TDX 路径。R2 再选择并接入真实替代来源，不能把 mock 接入称为支持其他行情服务商。

| 合约 | 要求 |
|---|---|
| 身份与能力 | sourceId、配置、来源说明；是否有完整日线、权息、基准、交易日历、增量同步能力 |
| 股票目录 | 稳定市场＋代码标识、名称和可用范围，避免跨市场代码冲突 |
| 原始日线 | 日期升序唯一、OHLC 以元计、成交量以股计、成交额以元计；定义停牌、缺值与未完成当日数据 |
| 权息/复权 | 提供可追溯权息或足以按推进日重建的复权信息；只提供“按今天前复权”的成品 K 线不能满足历史防未来 |
| 基准/覆盖范围 | 沪深 300、交易日历及覆盖证明；没有能力须显式标缺失，不能伪造零收益/已到期 |
| 同步/版本 | 增量结果、最后成功时间、修订标识、追加/修订分类；离线可读上次有效版本 |
| 训练绑定 | 创建时固定来源与数据口径，允许受控追加，不静默切换供应商或拼接不同复权数据 |

R2 待办：

- [ ] 对候选接口核实覆盖范围、更新延迟、权息准确性、历史深度、授权/费用、限流及离线缓存能力，再选首家。
- [ ] 按合约测试日期、OHLC、单位、市场、权息、复权及异常场景；与 TDX 共同日期样本对照，记录供应商历史修订策略。
- [ ] 行情缓存写训练器自有目录，TDX 目录继续只读；断网使用旧数据，凭证不写日志或明文文档。
- [ ] 缺权息的来源不能宣称支持完整前复权训练；缺基准时成绩单显示缺失，不能混入不具可比性的超额排名。
- [ ] 用未安装通达信的独立环境完成选股→更新→训练→结算验收。

## 6. 最小验收矩阵

| 场景 | 必须验证 |
|---|---|
| 本地追加日线 | 两处按钮同步日期/数量；全市场日期与个股日期不混淆 |
| 无变化、重复点击、多窗口 | 无变化不重画；同一来源单任务；状态结果一致 |
| 源失联、单市场失败、半写文件、权息失败 | 保留有效缓存与图表，不误报完整成功，恢复后可重试 |
| 等待数据 | 不结算；追加后可继续；真到期、周末、停牌、数据缺口及“尾部覆盖但中间漏数”分别验证 |
| 防未来与历史分页 | 刷新后日/周/月/更早历史均不越推进日；复权基准仍为推进日 |
| 训练状态保护 | currentDate/plannedEnd、现金/股数/成本、成交/权息流水、画线不因刷新改写；已结束训练不重开 |
| 历史修订 | 迁移后基线可用；OHLC/量额/权息变更保留旧版或明确阻断，不伪称恢复创建时历史 |
| 自动检查 | 启动一次、激活节流、手动立即更新、隐藏无轮询；无重复扫描风暴 |
| UI/UX | 840/1024/1440/1920 宽与深浅主题；顶部高度、账户位置、图表视窗及副图高度稳定，未完成绘图/待保存内容保留 |
| 数据源合约 | TDX＋假来源均通过；R2 真实来源另做无通达信全流程 |

开发先补能复现缺口的测试，再实现对应路径。使用临时 TDX 夹具和隔离 SQLite，主代理执行 Playwright 真实事件、截图并检查 UI 一致性与 UX。最终跑单测、构建、受影响旅程和 M2 对账；恢复普通生产构建后再提交用户验收。
