# 迁移与长期维护

状态：提案。上级入口：[文档架构](README.md)。本轮只设计，不执行现有文件搬移、历史拆分或自动清理。

## 现有文件如何处理

| 当前文件/内容 | 目标去向 | 处理方式 |
|---|---|---|
| 根AGENTS的全局硬边界 | 根AGENTS | 保留必要警示，局部细节下沉，父级仅路由 |
| architecture中的交互模式/私有API/监听器 | web模块主题页 | 按交互与库适配分开，模块索引链接 |
| architecture中的数据更新与版本边界 | server/src/data/docs | 当前行为与未满足目标分开写 |
| architecture中的跨层数据流 | docs/architecture | 保持短全局图和模块链接 |
| testing中的命令、门禁 | docs/engineering/testing | 保留现行责任，套件细节交给e2e/README |
| testing中的多轮结果和截图描述 | 原验收记录或新增历史记录 | 保留日期、首次失败和复跑来源，当前页只指向证据 |
| 开发计划中的现行产品行为 | docs/specs下各领域 | 使用稳定规则ID；不按页数机械切块 |
| 开发计划/M3执行中的阶段范围与待办 | work-items阶段卡及任务卡 | 区分实现、验证、用户接受和已集成 |
| known-invariants中的有效约束 | 对应规格/模块主题 | 原文件过渡为规则ID导航；只保留一个详细定义 |
| known-invariants中的未修项 | 单项任务卡 | 保留原发现证据与“尚未修复”状态 |
| changelog及长反馈过程 | archive按阶段/时期存档 | 当前入口只列简短结果与链接，不再追加长段落 |
| status中的审查Git快照、长目录图 | 审查记录、各级README | status保留当前任务及证据摘要 |
| verification现有报告/截图/TDX导出 | 原位保留，先增加索引 | 新记录采用按月份/record-id目录，旧证据不先全量搬迁 |
| 调研/讨论稿与未接受设计 | proposals或archive | 区分待定提案、历史研究与生效规范 |

历史正文尤其用户原话、验收意见和原始数据保留原文。允许新增历史标识和导航，不能“整理”成与当时不同的结论；迁移时记录原路径、后继路径和适用日期/版本。

## 分批实施

**批次一：增加入口和内容地图。** 列清文档及代码位置，建立根/模块README和必要AGENTS。先不改源码布局、不改门禁，不建立大量空目录。为各条硬约束记录新归属，检查是否存在无人承接的规则。

**批次二：拆开当前知识和历史。** 优先处理architecture、testing、changelog三份大文档；主题页迁移后修改入链。旧入口保留短兼容页指向新位置，禁止继续更新旧正文。兼容页标记为redirect，不复制完整内容。

**批次三：建立任务和证据记录。** 将真实未完成事项转为任务卡，迁移当前阶段的验收引用。历史任务无需全部重新结构化；证据不足标“未记录”，不得补造当时的SHA或验收结论。将status改为简短人工汇总视图。

**批次四：加入自动检查。** 先实现链接/元信息/文档影响检查；工作单格式跑通若干真实任务后，再生成状态和目录索引。所有新脚本需有必要的行为测试，并接入候选验收流程。

第一轮可选两个有代表性的模块：data与图表组件。验证局部任务读取顺畅后，再推广train和其余模块。此次文档拆分不应与图表源码大重构放在同一个任务中。

## 迁移验收

- 现有硬约束全部有新归属；父级与局部规则不存在静默放宽。
- 索引只列实际存在的入口；链接与重要锚点有效；旧入口能找到后继页。
- 现行规格、未完成任务、历史报告、提案标识清楚；搜索到旧材料不会误当当前指令。
- 用“数据发布失败”“图表分隔拖拽”“M3阶段冻结”三类任务走读，确认能定位必要规则和证据，且不要求读全仓文档。
- 新增模块、关闭任务、测试失败后复跑、用户验收、回滚、文件搬移这些事件，都有明确更新责任和检查路径。
- 两个worker并行更新不同任务时，不争写status/changelog；集成人能准确汇总。
- 源码、数据和运行配置未被文档迁移意外修改；执行与实际变更相称的检查，纯文档迁移无需冒充一次应用全量验收。

预算是预警，不能压过完整性。超过预算的正文要么有明确理由，要么按独立问题拆分，不能截断规则或证据。

## 长期防止再次膨胀

每次新增文件先判断是否有明确读者和任务；能写进现有主题的一小段就不另建文件。出现独立主题、不同owner或不同生命周期时再拆页。

每个目录只维护本层入口。首选根据README/正文元信息生成大目录清单；人工只写“何时读”的说明，避免维护一棵重复的全仓树。

任务关闭后从默认活动索引移出，路径不动。过时规范标superseded并指向后继；仍有效的决策继续被当前规格引用。月度或阶段收尾时做历史整理，不把每次交付变成全仓清扫。

临时运行目录、压缩缓存与正式证据分开：Headroom缓存继续使用全局 `$CODEX_HOME/headroom-cache`；运行临时产物按run隔离；正式选定证据进入verification。临时目录可按保留策略清理，必须先核对路径、进程和引用；失败证据、用户数据、未接受成果不能自动按年龄删除。

旧链接被外部使用时保留兼容入口。需要整体删除或搬迁大量历史证据时另列可审查清单，不把这类操作藏在普通文档同步里。

首轮观测读取字符量、定位所需跳转、规则漏读、重复状态数量、文档返工和失效链接。若索引层次增加却没有减少误读，应合并无价值中间层。
