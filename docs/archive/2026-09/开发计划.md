## 二、现行产品规格

### 2.1 训练流程与边界

手动选股 → 选择 1M/3M/6M/1Y/2Y 档位及起始日 → 加载历史 → 按日推进并买卖 → 提前结算、到期结算或放弃 → 基础结算。完整成绩单、排行和复盘由 M4 补齐。

- 单训练进行；开新训练前须结算或放弃当前训练。
- 默认资金 100 万，创建时可改；不设交易笔数门槛和破产线，允许长期空仓。
- V1 明示股票和日期。随机股票＋随机时间真盲测在 V2；服务端保留存量盲训兼容，V1 创建页无双盲开关。
- 更新数据不得更改当前训练日、计划结束日或自动重开已结算训练。
- **待修缺口**：目前无下一根本地日线就自动结算。R0 须区分“等待数据”和“真实到期”，不能把源数据暂缺记录成完整周期成绩。

### 2.2 图表与交互

- 日/周/月观察周期，推进粒度恒为日；MA25/60/144＋VOL＋MACD 已在 V1。
- 初始最多载入 **1040 根（840＋200 根均线暖机）**；实际同屏上限 **840 根**，缩放 1～840，默认约 150。向左动态加载更早历史，840 不是总加载量。
- ↑ 放大、↓ 缩小，以视图右端为锚；←/→ 移动十字光标；Home 恢复默认视图；空格推进，B/S 买卖。
- `]` 日→周→月→日，`[` 反向。输入框、编辑弹层、自定义模式和未完成绘图按交互守卫隔离快捷键。
- 默认模式主副图空白区右向框选放大、左向框选缩小；多选模式框选只选画线。价格轴和副图分隔条不参与框选。
- 滚轮平移历史，价格轴滚轮缩放纵轴；程序化缩放前恢复纵轴自动适配。
- VOL/MACD 双击最大化、再双击恢复。分隔条原生 7px 命中带优先于框选、画线和多选，尺寸拖拽不得改变柱宽。
- 红涨绿跌、阳线空心/阴线实心；MACD 白 DIF、黄 DEA、实心红绿柱。深色主图、VOL、MACD、成交标记带均为纯黑，控件使用中性灰。
- 顶部紧凑，次要详情用浮层。当前推进日、实际可见末日及来源数据末日须分清；日期轴抽样刻度不作为数据截止依据。

### 2.3 交易、权息与成本

- 按当日原始收盘价成交；买入仓位以总权益计算，受现金约束向下取整到 100 股；卖出可按比例或股数，T+1 默认开。
- 费用默认关闭；开启后佣金万 2.5、最低 5 元，卖出印花税 0.05%。引擎已有费用/T+1 设置读取，用户设置界面仍待 M5。
- 现金分红入现金、送转增加股数、配股按现有足额自动认购口径处理；认购款增加取得成本，以 `position_events.cost_delta` 记录。
- 当前实现的权息处理位于前复权训练路径；M5 开放“不复权”默认配置前须核查账户权息一致性，显示方式不应改变真实持仓权益。
- 成本线＝剩余持仓取得成本÷当前股数；含买入费及配股款，减仓按比例结转，清仓重置；现金分红只入现金。成本线与账户同源，不再以历史复权成交股数单独重放。
- B/S 在图表下方独立窄条展示：橙底白字 B、天蓝底白字 S；密集同向聚合并可查看明细。成交明细保留真实价，图表投影使用 `chartPrice`。
- 涨跌停和流动性不模拟；停牌/非交易日不能简单等同于下载失败，结算须依据数据覆盖范围判断。

### 2.4 复权与防未来

- 默认前复权，创建训练时锁定显示模式。
- 训练行情统一走 **截断至推进日 → 前复权（基准＝推进日）→ 日/周/月聚合**，形成中周/月也不得包含未来日线。
- 运行中禁止原始 `/api/kline` 接口；训练接口与历史分页均按推进日截断。200 根均线暖机位于可见区之前的历史侧。
- 权息事件与账户同步入账，不能以“前复权已体现收益”为由省略。
- 当前直接读取外部 TDX 文件，尚无历史数据版本冻结。R1 须识别末尾追加与历史修订；跨来源及完整历史复现须记录来源/版本，不能无声混用新旧口径。

### 2.5 画线工具与保存

现有 **23 种**：线段、射线、直线、水平直线/线段/射线、垂直直线/线段/射线、平行直线、价格通道线、斐波那契线、画笔、价位线、矩形、圆圈、圆弧、箭头线、看涨箭头、看跌箭头、百分比线、诅咒线、文本。

- 默认黄色、1px 虚线；多选为黄芯白圈锚点并保留线体颜色。价格文字透明无填充并随对象颜色，百分比/斐波那契同时显示比例与价位。
- 诅咒线按高点→低点取点，仅保留两点均价的 50% 水平射线，从第二点时间向右延伸。
- 颜色、粗细、线型、端点价格编辑；主副图绘制、吸附、移动、多选、撤销/重做/清空均已实现。
- 文本锚定图表坐标；常用工具在自定义模式拖入、移出和排序，其余工具可折叠。保存状态固定占位，不挤动工具和账户。
- 按训练保存用户对象，存 timestamp/value 及语义窗格；引擎标记不进入画线历史。256 KiB、500 对象、单对象 256 锚点上限。
- 保存失败保留本地副本；首次读取失败不得以空数组覆盖服务器。原始 D 单元见 [M3 计划](../../M3-画线工具链-开发计划.md)。

### 2.6 日线更新与来源适配（已有首批实现，保护及读取合约待补齐）

详细分解、接口草案与验收矩阵见 [日线更新与数据源适配计划](../../日线更新与数据源适配-开发计划.md)。

- 首页及训练主页面均提供 **“更新日线”** 按钮，使用同一刷新服务；与已有“刷新图表”“回到最新 K 线”区分。
- 自动检查首版在应用启动及窗口重新激活时触发，节流合并；手动按钮随时可用。周期轮询、应用关闭后下载不在首版默认启用。
- TDX 来源只同步用户已经下载到本地的数据、目录和权息缓存，不操作通达信、不声称从网络下载行情。无变化时说明本地来源未变化。
- 状态区区分最近检查时间、来源最大日线日期、当前股票末日和训练推进日。全市场最大日期不代表所有股票均已更新。
- 刷新保持账户、成交、画线、视窗及训练边界；无变化不重建图表，失败不清空旧图，按钮状态不增加顶部高度。
- 数据源接口覆盖目录、原始日线、权息、基准、刷新结果与覆盖范围。先包装 TDX，再接无需 TDX 的真实来源；具体服务商尚未选定。

### 2.7 M4 排行与复盘（待开发）

- 5 档独立排行；完整周期与提前结算分组，放弃不入榜。完整成绩按收益率降序→最大回撤升序→胜率降序，最终以稳定键破平局；提前结算按收益率排序并显示实际天数。
- 指标：总收益率、最大回撤、胜率、盈亏比、交易次数、同期沪深 300 超额、权益曲线；成绩单包含成交明细。
- 实现前固定样例：部分卖出如何计平仓笔，未清仓、零交易、零亏损如何呈现；费用/权息归属；基准缺失与交易日对齐；重复结算幂等；数据不足不得冒充完整成绩。
- 复盘还原成交、画线和权益曲线；未来行情开放范围须与运行中禁原始行情一致，不能通过历史复盘旁路泄露当前训练未来。

### 2.8 M5 设置与交付（待开发）

- 设置 TDX 路径、初始资金默认值、费用、T+1、复权默认值、自动检查偏好；路径错误可恢复。
- 创建训练时保存交易规则及来源信息，设置只影响新训练。当前每笔成交读全局费用/T+1，须先补快照及旧训练兼容，避免历史规则漂移。
- 首次启动、无来源、空数据、读取失败、缺权息/基准均有可执行提示，保留离线使用路径。
- 数据库迁移备份/恢复、生产构建及安装→训练→结算→排行→复盘全流程验收；现有主题/热键/二次确认复用。

## 三、技术与实现边界

- Node 24＋TypeScript＋Fastify＋node:sqlite；Vue 3＋Vite＋klinecharts **10.0.3 钉定**。`npm start` 启动已有构建，先 `npm run build`。
- TDX 目录只读；仅写训练器 SQLite 和浏览器偏好。`.day` 为 32 字节日线记录，权息由 `gbbq` 解密。已有目录/权息增量刷新、扫描协调器和文件状态快照；统一所有更新入口及整批版本发布仍待实现。
- 实际表包括 `settings/stocks/adj_factors/cache_meta/trainings/trades/equity_curve/position_events/drawings/data_file_state/data_refresh_log`；M4 指标字段、可复现来源版本和训练规则快照待开发。
- 实际页面只有 Launcher/Training（含基础结算弹窗）；排行、复盘、设置导航仍禁用。目标目录图和接口草案不能当作已实现功能。
- 现有 API：env、stocks、kline、trainings 创建/active/id/bars/next/trade/settle/abandon、drawings GET/PUT，以及 `GET /api/data/status`、`POST /api/data/refresh`；参数以 `server/src/api.ts` 为准。
- 待新增 API：rankings、replay、settings；已有接口保留兼容。
- 架构和库内部依赖见 [architecture.md](../../ai/architecture.md)；不变量见 [known-invariants.md](../../ai/known-invariants.md)。

## 五、待处理事项与非目标

- 优先处理个股覆盖推断、目录/权息/快照分批提交及历史版本保护；目录暂不可读保留缓存已有实现，保持回归。具体差距见状态页 DATA-01～04。

## 六、开发与验收约定

开发者负责实现、回归、Playwright 真实交互、截图及 UI 一致性/UX 合理性检查，完成后由用户验收。允许子代理实现，主代理承担最终验收。沿用用户对 M3 的授权，不再逐工具等待确认。

本次文档整理不等于代码交付；后续每批实现按受影响范围测试并更新报告。浏览器测试使用隔离数据库，真实训练不得推进、下单、重开或用于清空测试。Journey 之后恢复普通生产构建，确认测试钩子未进入用户运行页面。
