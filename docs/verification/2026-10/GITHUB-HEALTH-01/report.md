## 邮件原因与修复

旧 Source checks 的 Windows/Ubuntu 两个任务均失败：干净检出先测试后编译，启动器测试找不到真实重启模块；部分断言仍使用旧的数据库、录像和页面契约，路径夹具也混用了 Windows 字符串与宿主文件路径。

工作流改为安装依赖、构建、完整单测，保留双平台矩阵及失败报告。测试同步当前契约，保留链接保护、事务回滚、隐私和进程身份断言；生产进程线索解析明确使用 `path.win32`。

完整复验还发现启动器测试超时后未等待正在启动的分离进程，造成清理遗漏。现先等待启动任务完成，再按原有 runId/PID 核验停止自己的服务；新增真实子进程回归已验证旧清理失败、新清理通过。

Fastify、fast-uri、brace-expansion 与 Vitest 已更新至修复版本，官方 npm 完整依赖审计为 0 漏洞。这一结果针对当前源码依赖，不代表重新构建过已发布安装包。
