# REC-01录制结构与压缩实测

2026-09-19。结论：用户操作简单，文件大主要来自当前草稿重复保存整份行情。推荐先改变存储表示，再对分享文件压缩；不增加自动停录。方案见[紧凑存储](../../../proposals/session-recorder/compact-storage.md)。

## 120次推进的构成

冻结600519 raw日线，当前接线每次推进产生1份chart=null和2份完整chart检查点。120次推进共361个检查点，其中241份包含1040根行情，累计保存250640条Bar副本；实际观察区间只有1160个独立日期。

| 内容 | 序列化大小 |
|---|---:|
| 行情数组 | 28,376,956字节（98.58%） |
| 全部操作事件 | 109,701字节（约107KiB） |
| 训练参数和账户快照 | 156,674字节 |
| 空画线集合 | 482字节 |
| 其余元信息、引用及标点 | 142,247字节 |
| 总计 | 28,786,060字节（约27.45MiB） |

事件包括started/finished，不是120次点按分别存了数十万字。之前真实Recorder探针约27.45MiB与本次构造同形语料相符；UUID和计时差异会造成少量字节变化。

## 同一数据的四种表示

| 场景 | 当前JSON | 当前JSON直接gzip | 版本增量JSON | 版本增量再gzip |
|---|---:|---:|---:|---:|
| 120次推进，不复权日K | 27.45MiB | 6.70MiB | 0.87MiB | 约144KiB |
| 两年484次推进，不复权日K | 110.63MiB | 26.87MiB | 3.48MiB | 约570KiB |
| 120次推进，前复权日K | 38.08MiB | 7.64MiB | 1.05MiB | 约160KiB |
| 两年前复权，每20日查看周/月/日K | 171.92MiB | 34.93MiB | 5.51MiB | 约934KiB |

另测“仅将完全相同的整份行情移到共享表”：120次raw为约13.99MiB，gzip后约3.30MiB。仅消掉同一步的双份副本仍保留跨日大量重复，收益有限。gzip有有限匹配窗口，不能代替结构去重。

版本增量实验保留全部事件、账户、图表状态及检查点，只将bars移为基础/增量并引用；没有删掉用户操作，也没有丢失拒单等结果来换体积。每32版强制完整基础，patch较大时退为全量基础。相同值复用，变更按日期替换；复权改变旧值时保留新版本，旧版继续可读。

两年样本跨2024-12-20、2025-06-26、2025-12-19、2026-06-26四个除权日期；周/月查看使用项目真实聚合函数，包含当时尚未收盘的周期。解压后逐检查点深度比较，不只比较最后一幅图。另有合成画线点、样式/文字、删除后恢复集合、主题、context与gap元信息的codec往返检查；这不等于真实绘图操作、交易引擎或gap生命周期验收。

## 复现与证据范围

命令：`node node_modules/tsx/dist/cli.mjs scripts/assess-recording-compression.ts <冻结sh600519.day> <同批gbbq> <result.json>`。脚本见[assess-recording-compression.ts](../../../../scripts/assess-recording-compression.ts)，结果见[result.json](result.json)。只读冻结行情和权息，不写TDX、个人SQLite、应用运行代码或既有schema。

这是独立的格式实验：时间与账户语料按当前接线构造，行情/前复权/聚合取真实样本及项目函数，gzip level=6。未调用交易引擎，矩阵场景不含买卖/画线，数据历史额外补载和更多股票仍需后续覆盖。Node离线耗时不能当浏览器写入或交互性能。每个恢复步骤只使用当前版本，不读取后续版本。

第一次扩展全检查点验证时脚本因多余右括号未通过TS变换，未修改应用；修正后完整重跑成功。失败原日志和复跑日志保存在Headroom全局缓存。最终报告、结果、脚本作为评估工件提交，生产迁移尚未实施。
