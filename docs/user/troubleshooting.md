# 常见问题

按现象排查。以下均针对 Windows 一键版；源码运行方式的问题先检查环境变量是否与[安装说明](install.md)一致。

## 双击 Start.cmd 后窗口一闪而过，或浏览器没有打开

1. 手动在浏览器访问 `http://127.0.0.1:8787`，可能服务其实已经启动。
2. 到数据目录（Windows 发布包默认为解压目录下的 `data`，源码运行默认为 `%USERPROFILE%\.a-share-kline-trainer`）查看日志文件，失败原因会写在那里；程序不会在失败时假装修复。没写 `port` 配置时，默认端口 8787 被系统保留或占用会**自动改用邻近可用端口**，控制台和页面顶部的提示条都会写明实际端口——浏览器没打开时先看控制台输出的地址。
3. 确认压缩包已经**完整解压**：在压缩软件窗口里直接双击运行会缺少文件。

## 启动提示"端口被系统保留"或"端口被占用"

端口规则（2026-09-30 起）分两种情况：

- **没在 `trainer.config.json` 里写 `port`（默认 8787）**：默认端口被 Windows 系统保留（WinNAT 排除端口段，每次开机可能漂移，常覆盖 8787 附近）或被其他程序占用时，启动器**自动改用邻近可用端口**并在控制台、页面顶部常驻提示实际端口。训练数据不受影响；但**浏览器历史录像按访问地址存放**，端口变化后旧录像要回到原地址查看。看重录像连续性的用户建议按下面的方法固定端口。
- **在 `trainer.config.json` 里显式写了 `port`**：这个端口必须被尊重，启动失败会**明确报错不换端口**。错误信息会指明端口是"被系统保留"还是"被其他程序占用"。

排查与处置：

1. 在命令提示符运行 `netsh int ipv4 show excludedportrange`，看 8787 是否落在某段"排除端口范围"内（这是系统保留段，重启后段会漂移）。被其他程序占用时用 `netstat -ano | findstr :8787` 找到占用进程。
2. 端口上是**本包启动、仍在正常运行的训练器**：不用再启动一份，直接访问对应地址；重复双击 `Start.cmd` 本来就会复用它。
3. 端口上是你从别的目录（旧副本、源码运行）启动的**另一份训练器**：不要结束它，回到原来那份使用；通常应沿用原来的端口和配置，而不是另配一个端口。
4. 端口上是其他程序：确认它是什么、能否正常关闭后再决定；不确定时**不要强行结束进程**，更简单的做法是在 `trainer.config.json` 里写 `"port": 8890`（示例）后先 `Stop.cmd` 再 `Start.cmd`。
5. 注意：换了端口，浏览器里的历史录像会"看不见"（它们按 `127.0.0.1:8787` 这个来源地址存放），改回原端口即可恢复；确实要换端口的，先导出重要录像。

## 提示找不到通达信目录 / 页面没有行情数据

1. 点击右上角“连接通达信”，在 Windows 目录选择器里确认**通达信安装根目录**，不是 `vipdoc` 子目录。也可以在解压目录的 `trainer.config.json` 中设置 `tdxRoot`。发布包保存成功后会自动重启并刷新连接状态。
2. JSON 里的路径要用双反斜杠：`"tdxRoot": "D:\path\to\tdx"`。
3. 确认目录里有所需文件：`vipdoc\sh\lday\*.day`、`vipdoc\sz\lday\*.day`、`T0002\hq_cache\gbbq` 和证券名称文件。清单见[安装说明](install.md)。
4. 目录对但没数据：先用你自己的通达信客户端下载盘后日线，再回到训练器点"更新日线"。训练器不会联网下载行情。

## 解压或路径相关的报错

- 必须右键"全部解压缩"，不能在压缩包内直接运行。
- 解压路径不要太深、避免特殊字符；放在普通目录（如 `D:\kline-trainer`）即可，不需要也不建议放进 `C:\Program Files`。
- 桌面图标指向解压目录里的 `Start.cmd`，移动、重命名目录或删除文件后图标会失效，回到新位置重新双击 `Create Shortcut.cmd`。

## 页面能打开但提示接口错误 / 一直空白

1. 刷新页面；确认地址栏是 `http://127.0.0.1:8787`（端口自动回退时以控制台/页面顶部提示的实际端口为准）。
2. **不要改用 `localhost` 访问**：它是与 `127.0.0.1` 不同的来源地址，浏览器会当成另一个站点，训练录像按来源地址分开存放，混用会看不到已有录像。页面打不开时先回到控制台提示的 `127.0.0.1` 地址排查，而不是换主机名。
3. 到数据目录查看日志，把其中的错误信息用于排查或反馈。
4. 换较新的 Microsoft Edge 或 Chrome 再试。

## 画线、成绩或录像不见了

- **训练、成交、画线**存在数据目录的 SQLite 数据库里。设置了 `databasePath` 或 `dataDir` 的，改回原值即可找回；删除或更换数据目录等于换了一套训练数据。
- **训练录像**存在浏览器的 IndexedDB 里：清理浏览器数据、换浏览器、换端口都会看不到。清理浏览器前先导出录像。
- 分辨方法：录像库空了是浏览器侧的问题；训练列表空了是数据库路径的问题。
- 早期版本保存的画线缺少复权基准信息时会按原值显示、不自动换算，位置不对可手动调整。

## 导出或导入录像失败

- 导出文件是 `.trainer-session.json.gz`；导入时选错文件会被拒绝，且不影响现有数据。
- 导入有大小限制：当前格式压缩文件约 25MiB、解压后约 128MiB；旧版 JSON 的迁移上限约 256MiB。超限会被拒绝。
- 旧版本导出的 JSON 仍可导入；不兼容的版本会明确提示，不会静默产生错误结果。导入的录像只能用于回放，不会恢复成可继续操作的训练。

## "更新日线"没有新数据 / 提示需要更新但明明是最新

- "更新日线"只重新扫描本地通达信文件。新交易日的数据要**先在通达信客户端里下载**，再到训练器里更新。
- "需要更新"的提示是按最近工作日推测的建议，法定节假日前后可能误报，以页面显示的来源数据末日为准。

## 升级后配置或数据"丢失"

- 新解压的目录里没有 `trainer.config.json`：从旧目录复制过来。
- Windows 发布包训练数据在默认数据目录（解压目录下的 `data`）里，升级时复制旧包的 `data`；源码运行默认数据目录为 `%USERPROFILE%\.a-share-kline-trainer`。只有你删除数据目录或改配置才会“换库”。
- 升级后浏览器看不到录像：多半是端口或浏览器变了，见上文"画线、成绩或录像不见了"。

## 界面显示异常（窗口太窄）

训练器界面按桌面浏览器设计，当前已验证的最低窗口宽度为 **840px**；更窄的窗口（如手机竖屏的 390px）会出现横向裁切，属已知未支持场景。请把浏览器窗口拉宽到 840px 以上使用；后续版本如支持窄屏会另行说明。

## 备份前先停止训练器

推荐使用页面左侧栏的“退出”按钮做**保存并退出**：它等待画线、录像保存完成并正常关闭数据库后停止服务。之后复制整个数据目录。若自定义了 `databasePath`，连同该文件旁同名的 `-wal`、`-shm` 文件一起复制；不要只复制主数据库或手动删除这些附属文件。源码运行时在服务终端按 Ctrl+C。录像另行导出，见[用户指南](README.md)。

## 点了"保存并退出"但提示退出未完成

- **提示其他页面未确认**：还有别的训练器页面打开。到那些页面上确认"保存并退出"，或在那里选择"拒绝"后再回到本页重试；关闭多余的训练器标签页后重试也可以。超过限时未确认会自动取消退出，服务不会停止。
- **提示有进行中的训练**：退出不会自动结算或放弃训练，请先结束本局或放弃后再退出。
- **提示排空超时/关闭失败**：在途请求未能在限时内完成，服务已保持运行。稍等片刻重试；反复失败时重启浏览器再试。
- 应急兜底：`Stop.cmd` 会做身份核验后**强制结束**进程，不等待页面保存——只在页面完全无法使用时使用，未保存的画线可能丢最后一次修改（本地备份通常还在，见画线一节）。数据库始终保留。

## 仍有问题

先确认使用的是 [Releases](https://github.com/m1kuStark/kline-trainer/releases) 上的最新版本；仍无法解决时到 GitHub Issues 反馈，附上数据目录里的日志文本即可，**不要附个人交易数据、数据库文件或通达信目录内容**。
# 通达信连接

应用不会自动扫描通达信安装位置，也不会读取进程信息。首次使用或需要更换目录时，点击右上角“连接通达信”，在 Windows 资源管理器中选择包含 `vipdoc` 与 `T0002` 的通达信根目录并确认。目录结构检查失败时不会覆盖原有选择，请按提示重新选择；开发运行方式保存后需重启服务，发布版会在校验成功后自动重启并刷新连接状态。
