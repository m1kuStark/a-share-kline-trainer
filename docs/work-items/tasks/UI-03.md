## 用户反馈原文口径（2026-09-29，8899 测试包）

1. 起始日默认是行情最新日期，选择训练周期时起始日不对应跳转；要求周期点击后起始日从最新日期往回调对应周期长度（2年→2024-09-28、1个月→2026-08-28）。
2. 自定义范围的范围模式/起始日等多组控件繁琐重复；收敛为 K 线根数＋起始日期，系统自动校验结束日是否超过最新数据，超过则提醒并默认只训练到最新数据截止日。
3. 生成范围预览意义不明（时灵时不灵；已选股票后仍罗列候选）；改为自动校验。选股拆成代码/名称两个文本框：任一填写另一框补全，清空任一框双清；匹配不到提示写错；名称支持前缀下拉与拼音首字母（GZMT→贵州茅台、GZ→贵字头）。

## 为何由用户发现而非测试覆盖（bug 反思）

- **周期不联动**：TRAIN-02 验收覆盖的是自定义范围表单的默认起点（rangeDate 纯函数＋e2e），五档周期的起始日联动在 first-use-batch 规则里写了（"用户点击周期时…填入起始日"）但实现从未落地，e2e 断言只盯 RANGE 分支——规格条款没有对应的失败测试。教训：验收通过的规格条款应逐条映射到断言，映射不到的条款要显式记为"未实现"而不是静默遗漏。
- **预览时灵时不灵＋罗列候选**：旧实现把"预览按钮禁用（未选股）"与"下拉建议残留"叠加，单步断言各自都过、组合体验无人验证。教训：交互组合（输入焦点×按钮状态×下拉可见性）需要一条真实点击链路断言（本卡 test 1 已补）。
- **拼音检索缺失**：此前搜索无任何口径级单测（子串实现属隐式行为）。教训：新增 stock-search 模块时同步建口径单测。

## 实现边界

- 服务端三种范围模式（preset/latest/bars）API 与旧训练兼容性不变；前端只暴露起始日+根数一档，超限收缩走 latest 预览取可用根数后以 bars 模式重校验，创建仍由服务端复核（不静默截短：提醒常驻展示）。
- 预设周期起始日锚点＝数据状态 sourceMaxDate（行情最新日），未扫描时回退上海今天；手动修改保留到下次周期点击（用户拍板口径：周期点击总是重新生成）。
- 拼音首字母在服务端计算（pinyin-pro 3.29.4，MIT，third-party/npm/pinyin-pro）；搜索口径＝代码/名称前缀优先＋子串兜底＋首字母前缀，空查询返回全部。
