## 背景

用户报告原文：「我注意到用户训练过程中，挂条件单的操作并没有被录像记录到，这是一种信息的丢失，需要补上」。

需求语义（用户拍板）：①挂条件单（创建）与撤销条件单两个操作必须录制进录像事件流；②回放观看时可见（跟随回放 UI 现有业务列表呈现机制）；③录像格式向后兼容，旧录像解码/回放/校验不受影响；④params 记录挂单关键信息（方向/类型/价格/数量/有效期等），outcome 记录 accepted/rejected/cancelled；⑤条件单触发成交（引擎侧自动成交）本次不录新事件。

## 实现口径

- **action 命名**：`training.order.create` / `training.order.cancel`——架构师建议名，读码确认与 `chart.drawing.create/undo` 三段式命名族一致，`training.*` 前缀标识训练域。
- **params（started 事件，用户提交意图）**：create＝`{ side, orderType, triggerPrice, shares, reason? }`（camelCase，口径同 training.trade 的请求负载风格；reason 空时省略）；cancel＝`{ orderId }`。
- **result（finished 事件，服务端权威结果）**：两者均带 `{ order: { id, side, orderType, triggerPrice, shares, expiresDate } }`（OrderView 最小子集，expiresDate 覆盖「有效期」；orderId 供撤单与挂单关联）。
- **outcome**：成功 accepted；失败走既有 recording.rejected（ApiError<500→rejected，否则 unknown）；暂停期间悬挂由录制器补 interrupted。
- **业务口径**：BUSINESS_ACTIONS 纳入两动作——挂单拒单按既有口径计入并标注，cancelled/interrupted 排除。
- **回放呈现**：dailyReplay orderLabel 生成「挂条件单 买入限价 200股 @12.50」式标签（优先 result.order，拒单回退 params）；SessionReplay 业务列表/状态条 dayText 自动呈现，视图零改动。
- **改动落点**：types.ts（ACTIONS+2）、businessEvents.ts（BUSINESS_ACTIONS+2）、replay.ts/dailyReplay.ts（标签表+orderLabel）、Training.vue（placeOrder/cancelOrder 接线+orderRecordingView 摘要函数）。validation/compactValidation 的 ACTION_SET 均由 ACTIONS 派生，自动扩展；compactCodec 事件原样透传，零改动。
